DeepL Translation API 接口文档
1. 基本信息

Base URL

https://deepl.samwu00.de5.net/


所有 API 请求都必须携带：

Authorization: Bearer YOUR_CLIENT_API_KEY

未携带或 Key 错误时：

{
  "success": false,
  "error": "Unauthorized"
}
2. 接口列表
方法	接口	需要 Key	用途
GET	/	✅	根路径
GET	/health	✅	服务状态
GET	/usage	✅	DeepL 用量
POST	/translate	✅	文本翻译

注意：根路径 / 不会公开 API 信息，也必须经过 Key 验证。

3. 身份认证

所有接口都使用 Bearer Token。

请求头：

Authorization: Bearer YOUR_CLIENT_API_KEY

例如：

Authorization: Bearer abc123456789

其中：

YOUR_CLIENT_API_KEY

就是你在 Cloudflare：

Variables and Secrets
→ Variables
→ CLIENT_API_KEY

中设置的值。

4. GET /

用于测试 Worker 是否可以访问。

请求
GET /
Authorization: Bearer YOUR_CLIENT_API_KEY
成功响应
{
  "success": false,
  "error": "Not Found"
}

当前版本不会返回 API 信息。

如果不带 Key：

{
  "success": false,
  "error": "Unauthorized"
}
5. GET /health

检查 Worker 是否正常运行。

请求
GET /health
Authorization: Bearer YOUR_CLIENT_API_KEY
成功响应
{
  "success": true,
  "status": "ok"
}
未授权
{
  "success": false,
  "error": "Unauthorized"
}
6. GET /usage

查询 DeepL API 当前累计字符使用情况。

请求
GET /usage
Authorization: Bearer YOUR_CLIENT_API_KEY
成功响应
{
  "success": true,
  "usage": {
    "character_count": 123456,
    "character_limit": 1000000,
    "remaining_characters": 876544,
    "used_percent": 12.35
  }
}

字段说明：

字段	类型	说明
character_count	Number	已使用字符数
character_limit	Number	当前 DeepL 字符额度
remaining_characters	Number	剩余字符
used_percent	Number	已使用百分比
7. POST /translate

核心翻译接口。

请求地址
POST BaseURL/translate
Headers
Authorization: Bearer YOUR_CLIENT_API_KEY
Content-Type: application/json
8. 最简单的请求
{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
完整请求
POST /translate HTTP/1.1
Host: BaseURL
Authorization: Bearer YOUR_CLIENT_API_KEY
Content-Type: application/json

{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
返回
{
  "success": true,
  "translation": "你好，世界",
  "detected_source_language": "EN",
  "target_language": "ZH",
  "usage": {
    "input_characters": 11,
    "chunks": 1
  },
  "provider": "deepl",
  "cached": false
}
9. 请求参数
text

主要文本参数。

{
  "text": "Hello world"
}

类型：

String

必填。

input

为了兼容部分 OpenAI 风格请求，也支持：

{
  "input": "Hello world",
  "target": "zh-CN"
}

等价于：

{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
q

同时兼容 Google Translate 风格：

{
  "q": "Hello world",
  "target": "zh-CN"
}
10. 目标语言

支持：

{
  "text": "Hello world",
  "target_lang": "zh-CN"
}

也可以：

{
  "text": "Hello world",
  "target": "zh"
}

当前代码会自动转换成 DeepL 使用的语言代码。

常用示例：

输入	DeepL
zh	ZH
zh-CN	ZH
zh-TW	ZH-HANT
en	EN-US
en-US	EN-US
en-GB	EN-GB
ja	JA
ko	KO
de	DE
fr	FR
es	ES
it	IT
ru	RU

也可以直接传 DeepL 语言代码，例如：

{
  "text": "こんにちは",
  "target_lang": "EN-US"
}
11. 源语言

默认情况下不指定源语言，由 DeepL 自动检测。

例如：

{
  "text": "こんにちは",
  "target_lang": "zh-CN"
}

也可以手动指定：

{
  "text": "こんにちは",
  "source_lang": "JA",
  "target_lang": "zh-CN"
}

同时支持：

{
  "text": "こんにちは",
  "source": "JA",
  "target": "zh-CN"
}
12. OpenAI/Google 风格兼容

你的接口目前支持三种文本字段：

标准
{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
OpenAI 风格
{
  "input": "Hello world",
  "target": "zh-CN"
}
Google 风格
{
  "q": "Hello world",
  "target": "zh-CN"
}

不过需要注意：这只是请求参数兼容，并不是完整兼容 OpenAI /v1/chat/completions 或 Google Translation API 的完整协议。

13. 长文本自动分段

接口最大接受：

50,000 字符

即：

MAX_INPUT_CHARS = 50000

例如：

{
  "text": "这里是一大段很长的文本……",
  "target_lang": "zh-CN"
}

Worker 会自动：

50,000 字符以内
        ↓
按段落分割
        ↓
按句子分割
        ↓
单段约 4,000 字符
        ↓
逐段发送 DeepL
        ↓
重新合并
        ↓
返回完整翻译

因此客户端不需要自己把长文本拆开。

14. 缓存

翻译结果会使用 Cloudflare Cache API 缓存。

当前配置：

604800 秒

也就是：

7 天

例如第一次：

Hello world
      ↓
DeepL
      ↓
翻译
      ↓
Cloudflare Cache

第二次请求相同：

Hello world
      ↓
Cloudflare Cache
      ↓
直接返回

返回结果中的：

"cached": false

表示本次没有命中缓存。

如果命中：

"cached": true

注意：Cloudflare Cache 是缓存机制，不是永久数据库，因此不能保证每个缓存条目一定完整保留 7 天。

15. 缓存判断

缓存 Key 根据以下内容生成：

文本
+
目标语言
+
源语言

所以：

{
  "text": "Hello",
  "target_lang": "zh-CN"
}

和：

{
  "text": "Hello",
  "target_lang": "ja"
}

不会共用缓存。

同样：

{
  "text": "Hello",
  "target_lang": "zh-CN",
  "source_lang": "EN"
}

和：

{
  "text": "Hello",
  "target_lang": "zh-CN"
}

也是不同缓存。

16. 错误响应
DeepL 限流

HTTP：

429 Too Many Requests

Worker 会自动重试，最多 3 次。

统一所有错误返回格式：

{
  "success": false,
  "code": "ERROR_CODE",
  "error": "简洁错误原因"
}

例如：

{
  "success": false,
  "code": "AUTH_INVALID",
  "error": "访问密钥无效"
}
规范的错误码
HTTP	错误码	错误原因
401	AUTH_REQUIRED	缺少访问密钥
401	AUTH_INVALID	访问密钥无效
503	AUTH_CONFIG_MISSING	服务密钥未配置
503	CONFIG_DEEPL_KEY_MISSING	DeepL 密钥未配置
400	INVALID_JSON	JSON 格式无效
400	INVALID_TEXT	text 必须为字符串
400	EMPTY_TEXT	文本不能为空
413	INPUT_TOO_LONG	输入文本过长
400	DEEPL_BAD_REQUEST	DeepL 请求无效
401	DEEPL_AUTH_FAILED	DeepL 密钥无效
403	DEEPL_FORBIDDEN	DeepL 访问被拒绝
404	DEEPL_NOT_FOUND	DeepL 接口不存在
429	DEEPL_RATE_LIMIT	DeepL 请求过于频繁
456	DEEPL_QUOTA_EXCEEDED	DeepL 配额已用尽
502	DEEPL_CONNECTION_FAILED	无法连接 DeepL
502	DEEPL_RESPONSE_INVALID	DeepL 响应无效
502	DEEPL_NO_TRANSLATION	DeepL 未返回翻译
500/502	DEEPL_SERVER_ERROR	DeepL 服务异常
502	USAGE_FAILED	无法获取 DeepL 用量
500	INTERNAL_ERROR	服务内部错误
404	NOT_FOUND	接口不存在
