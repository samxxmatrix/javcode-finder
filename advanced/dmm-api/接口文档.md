# DMM 番号查询 API 接口文档

## 基本信息

**Base URL**

```
https://<your-api-domain>/
```

（国内友好入口。后端链路：Cloudflare 边缘 → Vercel 东京 → DMM / FALENO）

所有 API 请求都必须携带 Key：

```
?key=YOUR_API_KEY
```

（Query 参数）

或者请求头：

```
x-api-key: YOUR_API_KEY
```

未携带或 Key 错误时：

```json
{
  "code": 40101,
  "error": "MISSING_API_KEY",
  "message": "API Key is missing. Provide via query parameter ?key= or Header x-api-key."
}
```

## 接口列表

| 方法 | 接口 | 需要 Key | 用途 |
| ---- | ---- | -------- | ---- |
| GET | /:code | ✅ | 按番号查询完整信息（推荐用法） |
| GET | /api?code=xxx | ✅ | 按番号查询完整信息（等价写法） |
| GET | /cid/:code | ✅ | 仅查 CID（轻量，跳过详情页） |
| GET | /faleno/:code | ✅ | FALENO 官网作品页查询（响应形状对齐 DMM，但 **不含 `quality`/`preview_quality`/`preview_qualities`**，见该节说明） |

可选参数：

| 参数 | 说明 |
| ---- | ---- |
| key | API Key（与 x-api-key 头二选一） |
| refresh=1 | 强制绕过缓存，重新抓取 DMM |
| debug=1 | 调试模式：返回抓取过程中间状态（排查用） |
| quality | 单请求覆盖档位偏好，形如 `quality=432p`。**只认 `NNNp`（3–4 位数字 + 小写/大写 p）**；该数字被当作"目标高度"，所以 `000p` 会挑最低档、`9999p` 会挑最高档——不设区间限制。缺省、或没有 `p` 后缀（如 `quality=1080`）才回落到默认区间 `[320,600]`。仅对 DMM 全量查询生效（`/cid`、`/faleno` 忽略它） |

## 字段说明

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| code | String | 查询的番号（大写） |
| cid | String | DMM 商品 ID（数字版优先） |
| channel | String | 通道：digital（数字配信）或 mono（通贩 DVD） |
| title | String | 介绍（作品介绍文，可能较长） |
| short_title | String | 标题（商品名） |
| cover_url | String | 封面大图；数字版为 awsimgsrc.dmm.co.jp，mono 为 pics.dmm.co.jp |
| preview_url | String | 预告片 mp4 地址（**已按档位规则选好档**，不再是最高档）；该片无预告片时为 null |
| preview_quality | String | 实际选中的档位标签（如 `432p`）；无法判定高度时为 null |
| preview_qualities | Array | 该片的档位表，按分辨率升序：`[{quality,height,resolution,bandwidth,url}]`。playlist 路径下是**该片真实枚举的档位**；模板探测路径下是**静态家族表的候选集**（探测过但 404 的档也会列出，此时 `resolution`/`bandwidth` 为 null，`quality` 可能为 null）。拿不到 playlist 且探测全失败时为空数组 |
| quality | Number 或 null | 本次请求实际生效的档位覆盖值（`?quality=432p` → `432`）；默认区间口径下为 null。**注意它参与缓存口径**：同一番号交替请求"默认"与"带 quality"会各自未命中并重算一次 |
| actresses | Array | 出演者名数组（源站顺序）；拿不到为 `[]`。数字版取自 FANZA GraphQL `actresses { name }`，mono 取自商品情報テーブル「出演者」行 |
| delivery_date | String 或 null | **配信開始日 / 配信日**的原始抓取值。数字版是 ISO 时间戳（如 `2026-09-30T15:00:00Z`，**JST 换算由扩展侧做**）；mono 页通常没有该标签 → null |
| sale_date | String 或 null | **商品発売日 / 発売日**的原始抓取值（mono 页实测标签是「発売日」，如 `2026/09/25`）。数字版一律 null：GraphQL 的 `saleStartDate` 实测比配信開始日早一个月，语义是予約/販売開始，不等于商品発売日 |
| v | Number | 条目口径版本（服务端内部用）。改动响应口径时会递增，旧缓存读到版本不符即当未命中并重算，不需要清 Redis。**当前 4**（2 → 3 = 新增上面三个字段；3 → 4 = 修复 digital 分支 `detail` 重组漏字段，v3 的空元数据条目必须整体作废重抓） |
| detail_url | String | DMM 详情页地址 |
| cached | Boolean | 本次是否命中缓存 |

> **扩展侧口径**：`actresses` / `delivery_date` / `sale_date` 都是**原始抓取值**；优先级（配信開始日/配信日 → 商品発売日/発売日）与 `YYYY-MM-DD` 归一化由扩展的 `src/lib/release-meta.ts` 完成（含 ISO 时间戳按 JST 取日期）。

注意：title 中的部分敏感字会被 DMM 打码显示为 ●，接口原样返回，不还原。

## 仅查 CID

```http
GET https://<your-api-domain>/cid/BDSM-091?key=YOUR_API_KEY
```

响应：

```json
{
  "v": 2,
  "code": "BDSM-091",
  "quality": null,
  "cid": "h_1096bdsm00091",
  "channel": "digital",
  "cached": false
}
```

只做数字版 GraphQL 搜索（无匹配时回退 mono 搜索页），不抓详情页，比完整查询快。

缓存优先复用完整查询的结果（同一番号完整查过则直接命中），否则用独立的 CID 缓存（Redis key 前缀 `CID:`）。

## 档位选择规则

`preview_url` 返回的是**按规则挑出来的一档**，不再是最高的那一档。默认口径：在 `[320p, 600p]` 区间内取**最接近中点 460p** 的档；距离相同取更轻（码率更低）的一档；区间内没有档位时取最靠近区间的那一侧。

| 片子家族 | 可用档位（实测） | 默认选中 |
| ---- | ---- | ---- |
| 主家族（`sm/dm/mmb/mhb/hmb/hhb`，文件名不带 `_w`/`_s`） | 144 / 288 / 432 / 576 / 720 / 1080（另有同分辨率的 `*s` 高码率兄弟与 4K） | `mmb` **432p** |
| 数字版家族（`_w` / `_s` 后缀） | 180 / 316 / 404（部分片多一档 404 高码率） | 距离 460 最近的 **404p** |

档位表来自 DMM 自己的 HLS master playlist（`sample2DMovie.hlsMovieUrl`）——**按片枚举，权威**；playlist 不可用时按静态家族表逐档 `Range: bytes=0-1` 探测，命中即停，全失败则保留 API 给的最高档 URL（绝不返回坏地址）。

区间边界可用环境变量覆盖：`PREVIEW_HEIGHT_MIN`（默认 `320`）、`PREVIEW_HEIGHT_MAX`（默认 `600`）；单请求用 `?quality=NNNp` 覆盖（覆盖时区间不参与）。探测路径另受总预算 `PROBE_BUDGET_MS`（默认 `12000`）约束——到点即放弃探测、保留原始最高档 URL（见"环境变量"一节的说明）。

### 缓存键卫生

缓存键只接受 `^[A-Z0-9][A-Z0-9._-]{1,31}$` 的入参（先 NFKC + trim + 大写）。**不满足就不读也不写缓存**，但请求照常返回——因此像 `任务名称:-MFYD-189` 这样的脏输入永远不会变成 Redis 键（它仍能查到，只是不进缓存）。

反代**不做番号识别**：有码正则、无码 T1/T2 规则只存在于扩展端一处；反代只判断"这串字能不能当键"（纯语法），所以扩展端新增番号类别不需要改反代、也不需要重新部署。

注意：**不要在这一层去前导零或补零**——`SSIS-001`、`BDSM-091`、`072126-100` 里的数字段是作品号的一部分。

### 错误分类：404 与 503

| 情形 | 响应 |
| ---- | ---- |
| 确认查无（两条搜索路径都明确无命中、或详情页 404/410/空壳） | `404` / `40401` `ITEM_NOT_FOUND` |
| **无法定性**：超时、网络错、非 404/410 的非 2xx（含 WAF 403）、年龄确认拦截页 | `503` / `50301` `SOURCE_UNAVAILABLE`，带 `Retry-After: 5` |
| 未预期的内部异常 | `500` / `50001` |

判定是**失败即错**：只有确认查无才报 404，其余一律 503——早前"数字版抖动 + mono 查无"会被错误地报成 404（客户端于是当成"番号不存在"）。

**本服务不做负缓存**（没有 `NF:` 键、没有 TTL）：失败一律不写缓存。这一点与姊妹服务 d2pass 不同——d2pass 的负缓存 6 小时之所以安全，是因为它有源站明确的 404/410 作为"确认"依据；DMM 的命中来自搜索排序（`limit: 10` + 规则过滤），是启发式的，冻结起来会把排名波动变成"6 小时查不到"。

## FALENO 作品页查询

```http
GET https://<your-api-domain>/faleno/FNS-263?key=YOUR_API_KEY
```

响应（元数据字段与 DMM 查询一致、`channel` 固定为 `faleno` 并多一个 `v`；**不含 `quality` / `preview_quality` / `preview_qualities`**——档位选择只作用于 DMM）：

```json
{
  "v": 3,
  "code": "FNS-263",
  "cid": "fns263",
  "channel": "faleno",
  "title": "撮影を重ねるごとにエロくなっていく柏木雫ちゃんの汗、潮、マ〇汁、…",
  "short_title": "【汗・潮・淫汁・お漏らし】柏木【雫】を搾り尽くす体液ダダ洩れアクメ覚醒SEX 柏木雫",
  "cover_url": "https://cdn.faleno.net/top/wp-content/uploads/2026/09/FNS-263_1200.jpg?output-quality=60",
  "preview_url": "https://cdn.faleno.net/top/wp-content/uploads/2026/09/FNS-263_PR.mp4",
  "actresses": ["柏木雫"],
  "delivery_date": "2026/10/2",
  "sale_date": "2026/11/05",
  "detail_url": "https://faleno.jp/top/works/fns263/",
  "cached": false
}
```

说明：

- 上游由环境变量 `FALENO_ORIGIN` 指定（默认 `https://faleno.jp`）。抓取地址固定带尾斜杠。
  **拦截口径（2026-11-02 实测更正）**：站点拦的是**大陆段**，不是"非日本出口"——
  大陆宽带不论带不带尾斜杠一律返回 XSERVER 403 拦截页；美国 / 东京（`hnd1`）出口则 200。
  因此"带斜杠就能过"的旧经验已不成立（尾斜杠不再是通行证，仍保留只为少一跳并与扩展端形状一致）。
  结论：本端点必须跑在**非大陆出口**（东京 `hnd1`）才能取名。
- 结果按 `FALENO:{CODE}` 缓存（复用 DMM 的 Redis 实例）；**资料齐全永久、资料不全 6 小时**（同上"字段完整性分级 TTL"）；`refresh=1` 强制重抓。
- 作品不存在时返回 404 / `40401 ITEM_NOT_FOUND`：上游 404，或上游以 200 返回
  「ページが見つかりませんでした」页面，两种都判查无。
- 该端点在东京 hnd1 运行，因此不受上述地域限制影响；媒体（封面/预告片 mp4）在
  `cdn.faleno.net`，实测国内可直连，故媒体不经本反代。

## 番号匹配规则

查询优先级：数字版（FANZA 動画配信）优先，没有才查 mono 通贩。

数字版走 FANZA GraphQL API 两步查询：

1. `legacySearchPPV` 按补零番号搜索拿 id（如 IPX-118 → ipx00118）
2. `ppvContent(id)` 拿详情（标题/介绍/封面/预告片）

mono 走 DMM 搜索页 + 详情页 HTML 抓取。

拿到候选列表后按规则挑选，防止抓错片：

| 优先级 | 规则 | 示例 |
| ------ | ---- | ---- |
| 1 | 归一化后精确一致 | IPX-118 → ipx00118 |
| 2 | 尾部精确匹配（标准版优先，特典后缀 a/b 排后） | HODV-22112 → 41hodv22112（跳过 41hodv22112a/b）；BDSM-091 → h_1096bdsm00091 |
| 3 | 包含番号 | 厂商前缀型 cid |
| 4 | 都不匹配 | 返回 404 |

归一化：小写、去分隔符、数字段去前导零（`ipx00118 ≡ ipx118`）。

实测挡住的场景：

- 搜索 IPX-118 时 DMM 把合集版 7ipx118 排在第一位，接口仍正确返回标准版
- 搜索不存在的 QQQ-000 时 DMM 模糊搜索会返回一堆 IQQQ 系列，接口正确返回 404
- 50 个番号抽样实测：DMM 生态内数字版覆盖率约 95%，覆盖不到自动回退 mono；素人系（SIRO/259LUXU/300NTK/200GANA）与 FC2 不在 DMM 生态内，双通道均查不到。

## 缓存

查询结果缓存在 Redis（东京区域）。**资料齐全的条目永久保存（无过期时间）；资料不全的条目只缓存 6 小时**（见下"字段完整性分级 TTL"）。

第一次查询：

```text
GET /BDSM-091
      ↓ 未命中
抓取 DMM 搜索页 + 详情页
      ↓
写入 Redis
      ↓
返回 cached: false（约 4-5 秒）
```

第二次查询：

```text
GET /BDSM-091
      ↓ 命中
Redis
      ↓
返回 cached: true（约 0.5 秒）
```

强制刷新：

```http
GET /BDSM-091?key=xxx&refresh=1
```

绕过缓存重新抓取，并覆盖缓存。

### 字段完整性分级 TTL

条目里 `title` / `cover_url` / `preview_url` **任一缺失**（`null` 或空白）时，写入缓存只给 **6 小时**（`EX 21600`）；三者齐全则**永久**保存。

| 情况 | 缓存时长 | 理由 |
| ---- | ---- | ---- |
| 标题 / 封面 / 预告片齐全 | 永久 | 没有"内容会补齐"的风险，长期缓存省源站与 Redis 往返 |
| 缺任一（如只查到 `cid`、没有封面或预告片） | 6 小时 | 源站后来补齐封面/预告片时，最迟一个 TTL 就能自动生效——否则永久缓存会**永远**返回 `null`，只能人工 `refresh=1` |

- **`CID:` 前缀条目（`?only=cid` 写入）不设 TTL**：它按设计就只有 `cid`/`channel`，重抓拿不到任何增量，加短 TTL 只会让 `only=cid` 查询定期白跑源站。
- 分级只看这三个字段（`preview_qualities` 等派生值跟着走）。
- 可用环境变量 `INCOMPLETE_CACHE_TTL_SECONDS` 调整（默认 `21600`；设为 `0` = 关闭该策略，一律永久缓存）。
- ⚠️ 命中缓存时**不检查**条目是否"过期到该重抓"——过期由 Redis 的 `EX` 负责；`EX` 到期后键消失，下一次请求自然回源。

注意：Redis 免费档无持久化，服务维护/重启时缓存可能丢失，接口会自动重新抓取兜底，不影响正确性。

## 错误响应

统一格式：

```json
{
  "code": 40401,
  "error": "ITEM_NOT_FOUND",
  "message": "Item not found for code: BDSM-091"
}
```

错误码表：

| HTTP | code | error | 原因 |
| ---- | ---- | ----- | ---- |
| 400 | 40001 | MISSING_CODE | 缺少番号参数 |
| 401 | 40101 | MISSING_API_KEY | 缺少 API Key |
| 403 | 40301 | INVALID_API_KEY | API Key 错误 |
| 404 | 40401 | ITEM_NOT_FOUND | **确认查无**：搜索两路都明确无命中，或详情页 404/410/空壳页 |
| 503 | 50301 | SOURCE_UNAVAILABLE | **无法定性**：超时、网络错、非 404/410 的非 2xx（含 WAF 403）、年龄确认拦截页。响应带 `Retry-After: 5`，且**不写任何缓存** |
| 500 | 50001 | INTERNAL_SERVER_ERROR | 未预期的内部异常 |

注意：`503` 与 `404` 的分离是刻意的——只有**确认查无**才是 404，其余一律 503。早前把上游抖动报成 404，客户端会当成"番号不存在"而不重试。判定是"失败即错"，未知 outcome 也归 503。

> `/faleno/*` 目前仍沿用旧口径：非 404 的失败（WAF 403、5xx）报 `50001`，不报 50301——它有自己的错误处理，本次未改。

## 调试接口

```http
GET /BDSM-091?key=xxx&debug=1
```

返回**反爬/拦截排查**用的中间状态（搜索页大小、CID 提取结果、出口 IP 等）。正常业务不要调用。

> ⚠️ **不覆盖档位与错误分类**：`debug=1` 在档位选择与定性逻辑之前就返回，所以它不显示 playlist 档位表、每档高度、命中理由或分类依据。要看这些请用正常响应里的 `preview_qualities` / `preview_quality`，以及本地两套套件（`tools/dmm-quality-unit.mjs`、`tools/dmm-proxy-stub.mjs`）。

## 部署

> 完整步骤（Vercel CLI / Dashboard 两种部署方式、环境变量、Upstash Redis 集成、部署后验证清单、排查表与 Cloudflare 反代）见 **[dmm-api部署指南.md](./部署指南.md)**。下面是结论性摘要。

架构：Cloudflare 反代 Worker → Vercel Function（东京 hnd1）→ DMM

后端代码在 `advanced/dmm-api/vercel-dmm/` 目录。

### 1. 部署 Vercel

在 Vercel 导入 `advanced/dmm-api/vercel-dmm` 目录（package.json + vercel.json + api/index.js + **lib/*.js**）。

> ⚠️ 只拷 `api/` 会缺 `../lib/preview-quality.js` 等三个纯函数模块，函数会在 `ERR_MODULE_NOT_FOUND` 上全线 500。手工拷贝时**整个 `advanced/dmm-api/vercel-dmm` 目录**（含 `lib/`）一起拷。

关键配置：

- vercel.json 的 `functions.regions` 锁定 hnd1（东京）：DMM 会拦截 Cloudflare 出口 IP，东京 Vercel 出口实测可用
- vercel.json 的 rewrites 支持 `/:code` 与 `/cid/:code` 两种路径

环境变量（均可选）：

- `API_KEY`：设置后所有请求必须携带 Key
- `REDIS_URL`：Vercel Marketplace 集成 Upstash Redis 后自动注入
- `FALENO_ORIGIN`：FALENO 源站，默认 `https://faleno.jp`
- `PREVIEW_HEIGHT_MIN` / `PREVIEW_HEIGHT_MAX`：档位偏好区间，默认 `320` / `600`（空白/非法/缺失一律回落默认）
- `PROBE_BUDGET_MS`：**探测总预算**，默认 `12000`。playlist 不可用时才走探测（主家族最多 7 档 × 单档 5s = 35s），加上失败的 playlist 与两次 GraphQL 会贴住 `maxDuration: 60`；到点即整体放弃、保留原始最高档 URL。设为 `0` 等于**关闭探测**（每次直接回退原 URL）
- `INCOMPLETE_CACHE_TTL_SECONDS`：**资料不全条目的缓存秒数**，默认 `21600`（6 小时）。标题/封面/预告片任一缺失时按此值下发 `EX`；设为 `0` = 关闭该策略（一律永久缓存）

⚠️ **不要把敏感文件放进 `advanced/dmm-api/vercel-dmm/`**：本项目根目录下的普通文件会被**公开静态托管**
（实测放一个 `canary.txt` 上去可被 200 直接读取），`.env*` 虽然实测不会被静态放出（会落到
`/:code` 反代拿 401），但没有任何理由冒险。仓库已加 `.vercelignore` 排除 `.env*` / `node_modules`；
本地联调用的 Key 放**仓库外**的私有文件（不要在 Vercel 项目目录里，且 `docs/` 不进 git）。

### 2. 部署 Cloudflare 反代

创建 Worker，粘贴 `advanced/adaptive-proxy.js` 内容，绑定自定义域名。

作用：vercel.app 域名对国内访问不友好，CF 边缘提供国内入口；请求原样转发 Vercel，Key 校验与 Redis 缓存在 Vercel 层完成。

### 3. 验证

```http
GET /BDSM-091?key=xxx
```

正常返回番号数据即部署成功。

如果返回 500，加 `debug=1` 查看抓取中间状态（出口 IP、搜索页大小、GraphQL 命中情况），排查 geo 拦截或 cookie 流程问题。
