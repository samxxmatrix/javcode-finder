# dmm-api 部署指南（Vercel）

把 DMM / FALENO 番号查询后端部署到你自己的 Vercel 项目。接口契约见 [`接口文档.md`](./接口文档.md)。

> 本文只写占位符。你需要的密钥、项目名、域名请自己保管在**不入库**的文件里（例如 `advanced/SECRETS.local.md`），不要写进本文或任何会提交的东西。

> ## ⚠️ 部署前必读：必须「日本出口」，且反代 ≠ 封面/视频可达
>
> 1. **本服务必须部署在东京区域（`hnd1`）**。DMM 拦截非日本出口、FALENO 大量 403，非日本区域部署大概率整站 500（详见第 0 节「区域为什么不可选」）。
> 2. **反代只解决「查询」**。接口返回的 `cover_url` / `preview_url` 是 `pics.dmm.co.jp`、`cc3001.dmm.co.jp` 等**源站直链**，浏览器加载它们**仍需日本 IP**。即使用东京区域部署好反代，**大陆 / 非日本节点的浏览器仍可能裂图、黑屏**——除非浏览器侧本身能访问日本源站，或你额外部署「媒体代理」把图片 / 视频也拐到日本出口转发。
>
> 简言之：**部署反代解决的是番号查询，不解决封面 / 视频直链的可达性。**

## 0. 部署形态

| 项 | 值 |
| --- | --- |
| 平台 | Vercel（Hobby 免费档可用） |
| 产物 | 一个 Node Serverless Function，无前端、无构建步骤 |
| 区域 | **必须 `hnd1`（东京）**，`vercel.json` 已锁定 |
| 依赖 | 运行时仅 `redis@^5`（可选，不配则静默降级为直接抓取） |
| 对外形态 | 接口挂在**根路径**：`/{code}`，不是 `/api/{code}` |
| 首次部署耗时 | 约 5–10 分钟（含建项目与环境变量） |

**区域为什么不可选**：DMM 拦截非日本出口（Cloudflare Workers 出口实测被拦）；FALENO 拦截**大陆段**——大陆宽带不论带不带尾斜杠一律 403（XSERVER 拦截页），美国 / 东京出口均 200（2026-11-02 实测更正：尾斜杠不是通行证）。换区域大概率整站 500。

**区域是怎么生效的**：本项目在 `vercel.json` 的 `functions["api/index.js"].regions` 里**按函数**锁定 `hnd1`，它会覆盖项目级设置（项目面板里的 Region 可能是别的值，属正常）。部署后仍要核对一次：响应头 `x-vercel-id` 的**后一段**必须是 `hnd1`（形如 `sin1::hnd1::…`，前一段是你连的边缘节点）。

## 1. 前置条件

- Vercel 账号（Hobby 即可；注意 Hobby 限非商业用途）
- Node.js 18+（仅本地用于 CLI 与 `npm install`；`redis@^5` 要求 18+）
- Vercel CLI：`npm i -g vercel`，或全程用 `npx vercel`
- 一个自己生成的 API Key（例如 `openssl rand -hex 24`）
- Redis（可选）：Vercel Marketplace 的 Upstash 集成，免费档够用

## 2. 部署根与必须项

部署根是 `advanced/dmm-api/vercel-dmm/`。**Vercel 只认这个目录**，外层没有运行时文件。

| 文件 | 作用 |
| --- | --- |
| `api/index.js` | 函数主体：鉴权、抓取、选档、缓存、错误分类、调试探针 |
| `lib/preview-quality.js` | 播放列表解析、档位解析与选择 |
| `lib/cache-entry.js` | 缓存版本号、键名卫生守门、条目可用性 |
| `lib/upstream-outcome.js` | 404 / 503 定性、拦截页判定 |
| `vercel.json` | 锁定 `regions: ["hnd1"]`、`maxDuration: 60`、三条路径重写 |
| `package.json` | 唯一依赖 `redis@^5`，`"type": "module"` |
| `.vercelignore` | 排除 `.env*`、`node_modules`、`*.log` |

> `lib/` 必须随 `api/` 一起部署。只拷 `api/` 会让函数在 `ERR_MODULE_NOT_FOUND` 上全线 500，而且错误只出现在运行时日志里，很容易误判成"上游挂了"。

## 3. 方式 A：Vercel CLI（推荐）

```bash
cd advanced/dmm-api/vercel-dmm
npm install          # 只为本地脚本与依赖解析；node_modules 不会上传
vercel login
vercel link          # 首次：新项目选 "No"，项目名自定，Root Directory 保持 ./
```

`vercel link` 会在当前目录生成 `.vercel/project.json`（含 `projectId` / `orgId`）。**这个目录不要提交、不要外传**，仓库里的 `.gitignore` 已排除它。

> 如果这个目录曾经 link 过别的项目（或你 fork 了别人的仓库），先删掉 `advanced/dmm-api/vercel-dmm/.vercel/` 再 `vercel link`，否则会一直往旧项目推。

### 3.1 免登录部署（CI 或不想用本机登录态时）

在 Vercel 账号设置里创建一个 Access Token，然后：

```bash
vercel link --token "$VERCEL_TOKEN"        # 首次关联
vercel --prod --token "$VERCEL_TOKEN"      # 之后每次部署
```

Token 等同于账号的部署权限，按密钥对待：放环境变量或私有文件，绝不入库。

### 3.2 环境变量

```bash
vercel env add API_KEY production          # 必配
vercel env add REDIS_URL production        # 建议
vercel env add FALENO_ORIGIN production    # 可选，默认 https://faleno.jp
vercel env ls
vercel env rm API_KEY production
```

> 改完环境变量**必须重新部署一次**才生效。

### 3.3 部署

```bash
vercel --prod
```

输出末尾会给出两个域名：一个带部署哈希的 Production 域名，一个是项目别名（`https://<项目名>.vercel.app`）。**对外统一用项目别名**，它不随部署变化。去掉 `--prod` 就是只发预览，不影响生产。

### 3.4 自定义域名（可选）

Dashboard → 项目 → Settings → Domains → 添加域名并按提示配 CNAME。配好之后 base URL 就是 `https://api.example.com`，**不要**再加路径前缀——接口本来就在根路径。

## 4. 方式 B：Dashboard 导入 Git 仓库

适合"push 即自动部署"。

1. 把 `vercel-dmm/` 目录作为独立仓库推送（或在 Vercel 导入本仓库后指定子目录）。
2. Dashboard → **Add New… → Project → Import Git Repository**。
3. **Root Directory**：指向 `advanced/dmm-api/vercel-dmm`（如果导入的是整仓）。
4. **Framework Preset**：`Other`；Build Command / Output Directory 留空（没有构建产物）。
5. **Environment Variables**：按第 5 节添加，Environment 勾 Production。
6. Deploy。之后每次 push 到生产分支自动重新部署。
7. 部署完确认 Functions 面板里只有一个 `api/index.js`，**Region 为 Tokyo (hnd1)**。如果区域不对，说明 `vercel.json` 没被识别，先查 Root Directory。

## 5. 环境变量全表

### 5.1 必配

| 变量 | 说明 |
| --- | --- |
| `API_KEY` | 设置后所有请求需带 `?key=` 或 `x-api-key`。**不设置 = 接口对全网开放**，任何人都能消耗你的函数额度。 |

### 5.2 建议

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `REDIS_URL` | 空 | Redis 连接串。为空则每次真实抓取（首次 4–5 秒）。集成通常自动注入；若注入的是别的变量名，手填一个同名 `REDIS_URL` 即可 |
| `FALENO_ORIGIN` | `https://faleno.jp` | FALENO 源站，只在换源时需要改 |

### 5.3 调优（一般不用动）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PREVIEW_HEIGHT_MIN` / `PREVIEW_HEIGHT_MAX` | `320` / `600` | 预告片档位的偏好区间：区间内取最接近中点（460）的一档，同距取更轻的。非法值一律回落默认 |
| `PROBE_BUDGET_MS` | `12000` | 探测总预算。只在播放列表不可用、需要逐档试的时候生效，避免贴住 `maxDuration: 60`。设 `0` 关闭探测 |
| `INCOMPLETE_CACHE_TTL_SECONDS` | `21600` | 资料不全（缺标题/封面/预告片任一）的条目按此 TTL 缓存；齐全的条目仍永久缓存。设 `0` 一律永久 |

## 6. 接 Upstash Redis（可选）

没有 Redis 时接口仍可用，只是首次请求要真实抓取（4–5 秒），不会出现 `cached: true`。接上后命中缓存约 0.5 秒。

1. Dashboard → 项目 → **Storage → Marketplace** → 选 **Upstash Redis** → 创建（免费档足够，选与函数同区域的）。
2. **Connect Project** 连到本项目，生产环境会自动注入连接串。
3. 回 Settings → Environment Variables，确认存在 **`REDIS_URL`**。不同版本的集成可能注入成 `KV_URL` / `KV_REST_API_URL` 等名字，而代码只读 `REDIS_URL`——没有就手动加一个同名变量，值填同一个连接串（`rediss://…`）。
4. **重新部署**，然后按第 7 节验证"二次请求 `cached: true`"。

注意事项：

- Redis 连不上时**不会报错**，而是静默降级为直接抓取。所以"没有 `cached: true`"不代表结果错，也不一定代表 Redis 挂了。
- 缓存**永久保存（无 TTL）**，要强制刷新某个番号用 `?refresh=1`。
- 免费档无持久化，维护/重启可能丢缓存；丢了会自动重抓，不影响正确性。

## 7. 部署后验证

把 `<base>` 换成你的项目别名域名。Windows 自带 `curl.exe`，下面命令可直接粘到 PowerShell。

### 7.1 函数活着 + 区域正确

```bash
curl.exe -s -D - -o NUL "<base>/cid/BDSM-091"
```

- 期望 **401** + `{"code":40101,"error":"MISSING_API_KEY",...}`。若返回 200，说明你没配 `API_KEY`，接口是**公开**的。
- 响应头 `x-vercel-id` 的第一段应当是边缘节点，**函数实际区域看后一段**（形如 `sin1::hnd1::…`）。没有 `hnd1` 说明没跑在东京，DMM/FALENO 很可能被拦。

### 7.2 鉴权

```bash
curl.exe -s "<base>/BDSM-091?key=WRONG_KEY"    # 期望 403 INVALID_API_KEY
curl.exe -s "<base>/BDSM-091?key=YOUR_KEY"     # 期望 200 + JSON
```

### 7.3 缓存

```bash
curl.exe -s "<base>/BDSM-091?key=YOUR_KEY"     # 立刻再打一次
```

第二次期望 **`"cached": true`** 且明显更快。仍是 `false` 就回第 6 节查 `REDIS_URL`。

### 7.4 FALENO

```bash
curl.exe -s "<base>/faleno/FNS-263?key=YOUR_KEY"
```

期望 200，`channel` 为 `faleno`，`preview_url` 指向 `.mp4`，`detail_url` 是 `faleno.jp` 的作品页。

### 7.5 查无与强制刷新

```bash
curl.exe -s "<base>/ZZZ-999?key=YOUR_KEY"              # 期望 404 ITEM_NOT_FOUND
curl.exe -s "<base>/BDSM-091?key=YOUR_KEY&refresh=1"   # 期望 200 且 cached:false
```

### 7.6 档位覆盖

```bash
curl.exe -s "<base>/BDSM-091?key=YOUR_KEY&refresh=1&quality=1080p"
```

期望 `preview_quality: "1080p"`。注意 `?quality=` 的数字是"目标高度"：不带 `p` 会被忽略；`0p` / `9999p` 这类极端值会挑最低 / 最高档，不受区间限制。

### 7.7 一键回归脚本（可选）

仓库里带了一套打在生产部署上的端到端断言（`tools/vercel-e2e.mjs`），覆盖首次 200、二次 `cached=true`、404、缺 Key 时的 401、档位落在区间内、`?quality=` 覆盖生效等。

```bash
PROXY_API_KEY="YOUR_KEY" node tools/vercel-e2e.mjs https://<你的域名>
```

默认地址可以在环境变量 `PROXY_BASE` 里指定，或写进不入库的私有文件。全部 PASS 即部署成功。

## 8. 在扩展里接入

1. 打开扩展侧边栏 → 设置 → **DMM API 地址**填你的 base URL（不带尾斜杠，带了也会被自动去掉）。
2. **DMM API Key** 填 `API_KEY` 的值。
3. 打开 **「启用 DMM 查询」** 开关。扩展会先做一次健康探测（`GET /cid/BDSM-091?key=…`），成功才保持开启，失败会回弹并提示。

Key 同时支持 `?key=` 与 `x-api-key` 头，CORS 已放开。

## 9. 可选：Cloudflare 反代

如果 `*.vercel.app` 在你的网络环境里访问不理想，可以用 [`advanced/adaptive-proxy.js`](../adaptive-proxy.js) 起一个 Cloudflare Worker 做入口：它把请求**原样转发**到 Vercel，鉴权与缓存仍留在 Vercel 层。

1. Cloudflare Dashboard → Workers & Pages → 新建 Worker，粘贴 `adaptive-proxy.js`。
2. 给 Worker 配上游域名（**改代码没必要**，它读环境变量 `DOMAIN`）：
   - 位置二选一，改完都要重新 Deploy：
     - Worker → Settings → Variables and Secrets → 加 `DOMAIN = <你的项目域名>`（带不带 `https://` 都行，可带路径前缀）
     - 或 wrangler 配置的 `[vars]`
   - `DOMAIN` 未配或非法时 Worker 返回 **404 空响应**；上游失败返回 **502 空响应**，原因只写进 Worker 日志，访客看不到任何配置信息。
3. 绑定自定义域名，扩展里的 DMM API 地址改成这个域名。

同一份脚本可以服务任意上游，换域名只改配置。

## 10. 安全

1. **不配 `API_KEY` = 接口完全公开**。Hobby 有额度限制，被刷会直接打爆。
2. **部署根里的普通文件会被公开静态托管**（实测放一个 `canary.txt` 上去能被 200 直接读取）。所以：密钥、`.env`、日志一律不要放进 `advanced/dmm-api/vercel-dmm/`；保留 `.vercelignore`。
3. **`.vercel/` 不要提交**（含 projectId / orgId）。
4. **`?key=` 会留在访问日志里**。介意就改用 `x-api-key` 头。
5. **缓存无 TTL**，上游改了标题或换了封面，需要 `?refresh=1` 手动刷新对应番号。
6. **不要改区域**，`hnd1` 是这个服务能不能工作的前提。

## 11. 排查表

| 现象 | 可能原因与处理 |
| --- | --- |
| 根路径 404 | 访问路径带多余前缀（接口在根路径），或 `vercel.json` 没被识别（Root Directory 指错） |
| 所有请求 401 | `API_KEY` 没配或未生效；`vercel env ls` 确认后重新部署 |
| 403 `INVALID_API_KEY` | Key 不匹配：注意 URL 编码、前后空格、CLI 粘贴时带入的换行 |
| 500 `INTERNAL_SERVER_ERROR` | 抓取被拦或上游改版。加 `&debug=1` 看中间状态（出口 IP、搜索页大小、GraphQL 命中情况），先确认区域是东京 |
| 200 但 `cached` 恒为 false | `REDIS_URL` 没配 / 变量名不对 / 没重新部署 |
| 首次 4–5 秒、偶发超时 | 正常（首次要抓搜索页 + 详情页）。确认 `maxDuration` 生效（`vercel.json` 已设 60） |
| 改了代码线上没变 | CLI 方式必须手动 `vercel --prod`；Git 方式检查是否 push 到生产分支、Root Directory 是否包含被改的文件 |
| 国内访问慢/不通 | 见第 9 节反代，或绑定国内可达的自定义域名 |
| 标题能查到但封面/视频裂图、黑屏 | 反代只解决查询，`cover_url`/`preview_url` 是源站直链，浏览器侧无日本出口 | 让浏览器走日本节点，或额外部署媒体代理（把图片/视频也拐到日本出口转发） |

看日志：Dashboard → Deployments → 选中部署 → Functions / Runtime Logs；或 `vercel logs <deployment-url>`。
