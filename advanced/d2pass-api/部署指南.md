# d2pass-api 部署指南（Vercel）

把 18 家无码站点的番号查询服务部署到你自己的 Vercel 项目。接口契约见 [`接口文档.md`](./接口文档.md)。

> 本文只写占位符。密钥、项目名、域名请自行保管在**不入库**的文件里（例如 `advanced/SECRETS.local.md`），不要写进会提交的任何东西。

> ## ⚠️ 部署前必读：必须「日本出口」，且反代 ≠ 封面/视频可达
>
> 1. **本服务必须部署在东京区域（`hnd1`）**。非日本出口访问这些无码站会大量 404/403，错误长得像「番号不存在」，极易查错方向（详见第 3.0 节）。
> 2. **反代只解决「查询」**。接口返回的 `cover_url` / `preview_url` 是各站点源站 CDN 直链，浏览器加载它们**仍需日本 IP**。即使用东京区域部署好反代，**大陆 / 非日本节点的浏览器仍可能裂图、黑屏**——除非浏览器侧本身能访问日本源站，或你额外部署「媒体代理」把图片 / 视频也拐到日本出口转发。
>
> 简言之：**部署反代解决的是番号查询，不解决封面 / 视频直链的可达性。**

## 0. 部署形态

| 项 | 值 |
| --- | --- |
| 平台 | Vercel（Hobby 可用，注意 Hobby 限非商业用途） |
| 产物 | 一个 Node Serverless Function，无前端、无构建步骤 |
| 区域 | **必须 `hnd1`（东京）**。它来自**项目设置** `serverlessFunctionRegion`，不在 `vercel.json` 里（本文用 `builds`，带不了 regions），每次部署前都要单独确认 |
| 依赖 | `redis@^5`（可选，不配则降级为内存缓存，正确但慢） |
| 对外形态 | 接口挂在**根路径**：`/{code}`、`/batch`、`/api?code=` |

**合规提示（请自行判断是否部署）**：这套服务抓取公开网页并返回封面/预告片直链。Vercel 的 AUP 对爬虫类负载与成人内容有限制，Hobby 档也明确限非商业用途。商用或长期使用建议升级套餐、改绑自有域名，或整体改用 Cloudflare Workers（KV 免费额度对"永久缓存"这种写入极少的场景反而更友好）。

## 3. 部署

### 3.0 部署前第一件事：确认区域是东京（`hnd1`）

这一步最容易漏，漏了的后果却是整站不可用——非日本出口访问源站会大量 404/403，而错误长得很像「番号不存在」，很容易查错方向。

**为什么区域不在 `vercel.json` 里**：本文用的是显式 `builds`，`builds` 没有 `regions` 字段（只有 `functions` 配置才有）。区域是**项目级设置**，跟部署命令无关。

| 场景 | 怎么设 |
| --- | --- |
| CLI 首次建的项目 | 区域通常是默认值（`iad1` / `sfo1`），**建完必须改**：Dashboard → 项目 → Settings → Functions → Region → 选 **Tokyo, Japan (hnd1)** |
| REST 方式部署 | `deploy-rest.mjs` 会把 `regions: ["hnd1"]` 随部署请求一起传（默认已是 `hnd1`，可用 `VERCEL_REGION` 覆盖） |
| 已有项目 | 沿用既有设置，不用每次改，但**换项目 / 换账号时必须重新确认** |

部署完立刻验证（这一步不要省）：

```bash
curl.exe -s -D - -o NUL "<base>/HEYZO-3953"
```

响应头 `x-vercel-id` 形如 `sin1::hnd1::…`：前面是边缘节点（你从哪连的），**后一段才是函数实际运行区域**。后一段不是 `hnd1` 就说明区域没设对，回去改设置后**重新部署**。

### 3.1 方式 A：Vercel CLI（推荐）

```bash
cd advanced/d2pass-api/vercel-d2pass
npm ci
vercel login
vercel link                     # 首次；新项目选 No，项目名自定，Root Directory 保持 ./
vercel env add API_KEY production
vercel env add REDIS_URL production
vercel --prod
```

`vercel link` 会生成 `.vercel/project.json`（含 `projectId` / `orgId`），**不要提交、不要外传**。

> 若这个目录曾 link 过别的项目（或你 fork 了别人的仓库），先删掉 `.vercel/` 再重新 link。

### 3.2 方式 B：Dashboard 导入

1. 把 `vercel-d2pass/` 作为独立仓库推送（或导入整仓并把 Root Directory 指到 `advanced/d2pass-api/vercel-d2pass`）。
2. Framework Preset 选 **Other**，Build Command / Output Directory 留空。
3. Settings → Environment Variables 逐条添加（第 5 节）。`vercel.json` 会自动生效。
4. Deploy。

### 3.3 方式 C：REST API（**备选**，只在跑不了 CLI 时用）

> 日常部署**走 3.1 的 CLI 就够了**，与姊妹项目 `dmm-api` 完全一致。本节只是兜底方案，适用两种情形：受限环境里 CLI 起不来，或 CI 里不想装 CLI。

某些受限环境里 Vercel CLI 会失败——它内部要 spawn 子进程并通过管道通信，可能被命名管道限制挡掉（表现为 `Failed to spawn get latest worker: EPIPE`）。此时直接调 REST API：

```bash
cd advanced/d2pass-api
# token 取值顺序：环境变量 VERCEL_TOKEN → 私有凭据文件 → 旧 token 文件
D2PASS_API_KEY="<你的 API Key>" node deploy-rest.mjs
```

脚本做四件事：建项目（已存在则复用）→ 写环境变量（只写必需的几项，不碰 `REDIS_URL`）→ 内联上传文件建生产部署 → 轮询到 `READY` 并打印地址。

可用环境变量覆盖默认值：`VERCEL_PROJECT`（项目名）、`VERCEL_TEAM_ID`（团队 scope，留空表示个人）、`VERCEL_REGION`（默认 `hnd1`）。

> 内联上传时若 `projectSettings.framework` 为 `null`，Vercel 不会把函数编译出来——所以 `vercel.json` 必须用显式 `builds`（见下节）。

## 4. `vercel.json` 为什么这样写

```json
{
  "builds": [
    { "src": "api/index.js", "use": "@vercel/node", "config": { "maxDuration": 60 } }
  ],
  "routes": [
    { "src": "/(.+)", "dest": "/api/index.js" }
  ]
}
```

三点都不是随意写的，改动前请先读：

1. **必须用显式 `builds`，不能用 `functions` + `rewrites`。** 实测用现代写法部署后 `functions: []`、`builds: []`，函数根本没被编译，访问任何路径都返回 Vercel 自己的 404。另外 `builds` 与 `functions` 两个键**不能共存**，`maxDuration` 要写在 `builds[].config` 里。
2. **catch-all 用 `/(.+)` 而不是 `/(.*)`。** `.+` 要求斜杠后至少一个字符，于是根路径 `/` 不匹配任何路由、直接返回平台 404。写成 `/(.*)` 的话根路径会进函数、撞上鉴权并返回 `MISSING_API_KEY`——等于告诉扫描者"这里是个要 key 的 API"。
   - 副作用：`/?code=xxx` 也会 404（路由只看路径不看 query）。这不是问题，对外写法只有 `/{code}` 与 `/api?code=`。
3. **区域不在这里配置。** `builds` 没有 `regions` 字段，区域来自项目设置 `serverlessFunctionRegion`（或走 `deploy-rest.mjs` 时随部署请求传）。这正是 3.0 节要求单独确认的原因——`vercel.json` 看着「什么都配好了」，但区域不在其中。

用 catch-all 之后，`/batch`、`/{code}`、`/api?code=` 的分发都在 `api/index.js` 里按 `pathname` 判断，不再依赖 `rewrites` 的顺序。

## 5. 环境变量

> 只有前两项是必需的。**其余全部有等价的内置默认值**（`verify-defaults.mjs` 逐项验证过），需要时再往面板里加，不要一次性全配——多一份配置就多一处漂移。

### 5.1 必需

| 变量 | 说明 |
| --- | --- |
| `API_KEY` | `?key=` 或 `x-api-key`。未配置则**接口完全公开** |

### 5.2 推荐

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `REDIS_URL` | 空 | Upstash 集成后自动注入。为空则每次实时解析（正确但慢） |
| `NEGATIVE_TTL_HOURS` | `6` | **负结果**（"没查到"这个结论）的缓存小时数。`0` = 也永久保存（不推荐，会把一次偶发失败永久判死）；更保守可以设 `24` |

> 正结果永久保存、不设 TTL——没有 `CACHE_TTL_DAYS` 这个变量。作品信息基本不变，也让冷启动成本只付一次。`refresh=1` 是唯一的强制更新手段。

### 5.3 调优（一般不用改）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `RATE_LIMIT_PER_MIN` | `120` | 每 Key 每分钟上限，超出 429 `RATE_LIMITED` |
| `BATCH_MAX` | `50` | 批量查询单次上限 |
| `SOURCE_TIMEOUT_MS` | `6000` | 单源站超时。实测冷连接首字节 1.7–2.8s，**设 3s 会出现假 404**，别调小 |
| `D2PASS_TIMEOUT_MS` | `4000` | 单次 D2Pass 搜索超时 |
| `TOTAL_BUDGET_MS` | `12000` | 单次解析总预算；剩余不足 30% 时跳过 D2Pass 阶段，直接返回源站信息 |
| `D2PASS_USE_RSC` | `true` | 给 D2Pass 请求加 `RSC: 1` 头（实测 407 KB → 51 KB，**务必保持开启**） |
| `FORCE_HTTPS_SOURCE` | `true` | 把源站回链强制改写为 https（**必须开启**：D2Pass 存的是 `http://`，直抓会 400） |
| `DISABLED_SITES` | 空 | 逗号分隔临时下线某些站，如 `nyoshin,kin8tengoku` |

### 5.4 预告片

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PREVIEW_ENABLED` | `true` | 关闭后 `preview_url` 恒为 `null`（批量列表场景可关，提速） |
| `PREVIEW_QUALITY_ORDER` | `480p,360p,240p,720p,1080p` | 清晰度偏好顺序。480p 体积约为 1080p 的 1/4（7.2 MB vs 29.3 MB） |
| `PREVIEW_MODE` | `auto` | `auto` = 先抽取真实值、失败再按档位构造；`page` 只抽取；`template` 只构造（最快，但可能拿到 302 地址） |
| `PREVIEW_VERIFY` | `true` | 逐档构造时发一次 `Range: bytes=0-1` 校验，非 206 就换下一档 |
| `PREVIEW_FOLLOW_REDIRECT` | `true` | 跟随 302 并记最终 URL（部分站点主域 302 到 `sample.` / `smovie.` 子域） |
| `PREVIEW_ALLOW_HLS` | `true` | 是否允许返回 `m3u8`（需扩展侧 hls.js 支持） |
| `PREVIEW_HEYZO_ORDER` | `sample_low,sample,sample_hd` | HEYZO 没有 `{q}p` 档位，只有这三档；默认取最轻的 `sample_low` |

### 5.5 受限站点代理（默认为空，不要急着配）

| 变量 | 说明 |
| --- | --- |
| `SITE_PROXY_NYOSHIN` | 该站专用出口，`http://user:pass@host:port` 或 `socks5://…` |
| `SITE_PROXY_KIN8TENGOKU` | 同上 |
| `SITE_PROXY_UNKOTARE` | 同上（该站疑似已整体迁移，配代理也未必有效） |

未配置时这三站**立即返回 503 `SOURCE_UNAVAILABLE`**（不重试、不挂起），不影响其余站点的延迟。

> **实测结论**：女体のしんぴ 已停止服务、金髪天國 详情页已失效——不是地域问题，**配代理是无效投入**。真实可解析覆盖率 16/18。

## 6. 上线验证

### 6.1 契约冒烟

| # | 请求 | 期望 |
| - | ---- | ---- |
| 1 | `/HEYZO-3953?key=…` | 200，`site_id: heyzo`，`cached: false` |
| 2 | 同一请求再打一次 | 200，`cached: true`（Redis 生效），耗时明显下降 |
| 3 | `/100126-100?key=…` | 200，`site_id: pacopacomama`，`preview_url` 含 `480p` |
| 4 | `/100426-001?key=…` | 200，`site_id: caribbeancom` |
| 5 | `/batch?codes=HEYZO-3953,100126-100,QQQ-000&key=…` | 200，`results` 3 条、`errors` 1 条 `40401` |
| 6 | 不带 key 访问 `/HEYZO-3953` | 401 `MISSING_API_KEY` |
| 7 | 根路径 `/` | 404（**不能**返回鉴权错误，原因见第 4 节） |

### 6.2 路由回归（这几条最能暴露归一化问题）

| 请求 | 期望片商 |
| --- | --- |
| `/100426-001`（连字符） | カリビアンコム |
| `/100426_01`（2 位下划线） | 10musume |
| `/100426_1267`（4 位下划线） | ムラムラ |
| `/100126_100`（3 位下划线） | パコパコママ |
| `/100126-100`（同数字改连字符） | カリビアンコム → 404 `ITEM_NOT_FOUND`（该站无此片） |

### 6.3 区域

```bash
curl.exe -s -D - -o NUL "<base>/HEYZO-3953"
```

期望 401，且 `x-vercel-id` 里能看到 `hnd1`。

### 6.4 性能与缓存

- 首次查询（`cached: false`）期望 1–3 秒；命中缓存 < 100 ms。
- `debug=1` 能看到：路由判定、候选站点、源站耗时、搜索尝试次数、回链校验结果、预告片来源（`json`/`page`/`template`）与命中档位。
- 在 Redis 控制台确认 `D2P:*` 键在增长且**没有 TTL**；`D2P:NF:*` 是负结果，有 TTL。
- ⚠️ CDN 会把响应缓存 24 小时，**复测一定要换 URL**（加个 `&_=2` 之类的无意义参数），否则测到的是边缘缓存而不是你的函数。

## 7. 运维脚本

三个脚本都在 `advanced/d2pass-api/` 下，默认只干跑。

| 脚本 | 用途 |
| --- | --- |
| `purge-test-cache.mjs` | 清掉测试写进 Redis 的缓存键。只删测试脚本里出现过的番号，**不用 `SCAN` 通配**，不会误伤正常缓存 |
| `trim-env.mjs` | 按白名单精简项目环境变量，默认保留 `API_KEY` / `REDIS_URL` 等必需项 |
| `deploy-rest.mjs` | 见 3.3 |

```bash
REDIS_URL="rediss://…" node purge-test-cache.mjs           # 干跑，只列将要删的键
REDIS_URL="rediss://…" node purge-test-cache.mjs --apply   # 真删
node trim-env.mjs            # 干跑
node trim-env.mjs --apply    # 真删（删完要重新部署才彻底生效）
```

> 删缓存是零风险的：这些键是纯缓存，不参与任何状态机，代价只是下次查同一个番号要重新解析。

## 8. 排查表

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 所有请求 401 | `API_KEY` 未配或未生效 | `vercel env ls` 确认，重新部署 |
| 访问任何路径都是平台 404 | 函数没被编译 | `vercel.json` 改成显式 `builds`（第 4 节） |
| 大面积 404 / 400 | 没强制 https | 确认 `FORCE_HTTPS_SOURCE=true` |
| 流量、耗时异常大 | 没加 `RSC` 头 | 确认 `D2PASS_USE_RSC=true` |
| 标题乱码 | 未按 charset 解码 | 部分站点是 EUC-JP，属适配器问题 |
| D2Pass 搜索总是 0 结果 | 未做片段回退 | 检查回退链：完整标题 → 首段 → 前 14 字 |
| 命中错片 | 缺回链校验 | 商品页回链里的番号必须与请求一致 |
| 全部 `cached: false` 且慢 | `REDIS_URL` 未注入 | 检查 Marketplace 集成 |
| 预告片档位不对 | 顺序没生效 | 检查 `PREVIEW_QUALITY_ORDER`；响应里的 `preview_quality` 会回显实际命中档位 |
| 某档 404 | 该站没有这一档 | 应自动回退下一档；全 404 则 `preview_url=null` |
| 预告片播不动（302） | 用了 www 主域 | 开 `PREVIEW_FOLLOW_REDIRECT`，让实现记最终 URL |
| 某站固定 404 | 站点停服/失效 | 先确认区域是 `hnd1`；仍失败不要配代理，直接接受 16/18 |
| 响应接近 60s | 超时预算失效 | 检查 `SOURCE_TIMEOUT_MS` / `TOTAL_BUDGET_MS` |
| 标题能查到但封面/视频裂图、黑屏 | 反代只解决查询，`cover_url`/`preview_url` 是各站源站直链，浏览器侧无日本出口 | 让浏览器走日本节点，或额外部署媒体代理（把图片/视频也拐到日本出口转发） |

## 9. 安全

1. **不配 `API_KEY` = 接口完全公开**。
2. **部署根里的普通文件会被公开静态托管**（姊妹项目实测：放一个 `canary.txt` 能被 200 读取）。密钥、`.env`、日志一律不要放进去；保留 `.vercelignore` 排除 `.env*`。
3. **`debug=1` 无条件生效**。它由 `API_KEY` 保护——所以 **key 一旦外泄，等于抓取过程也外泄**。这是刻意取舍：少一层开关，少一处"忘记关回来"的风险。
4. **`.vercel/` 不要提交**（含 projectId / orgId）。
