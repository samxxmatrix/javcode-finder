# D2Pass（无码源）番号查询 API 接口文档

> 状态：**已上线（Vercel 反向代理）** · 范围：番号 → 标题 / 封面 / **预告片** / 女优 / 发行日 / 源站链接 / D2Pass 商品链接
> 本文档只描述**接口契约**（端点、参数、响应、错误码、调用须知），面向部署方与调用方。
> 实现细节、路由规则、适配器、缓存内部设计、代码地图见 [`实现与维护`](../../docs/workbuddy_plan/2026-11-03-d2pass-api-implementation-maintenance.md)。
> 从零部署见 [`部署指南`](./部署指南.md)。

契约刻意对齐 [`dmm-api 接口文档`](../dmm-api/接口文档.md)：`?key=` 或 `x-api-key`、同一套错误码、同样的 `cached` 字段。扩展侧可用**同一套客户端代码**接入第二个源（只多一个 base URL）。

## 1. 接口列表

| 方法 | 接口 | 需要 Key | 用途 |
| ---- | ---- | -------- | ---- |
| GET | `/:code` | ✅ | 按番号查询（推荐写法，与 DMM 源一致） |
| GET | `/api?code=xxx` | ✅ | 等价写法 |
| GET | `/batch?codes=A,B,C` | ✅ | **批量查询**（扩展扫一页常有 10–50 个番号，强烈建议用这个） |

> 接口挂在根路径。根路径 `/` 与 `/?code=xxx` 故意返回平台 404，不进鉴权（避免暴露"这里是个要 key 的 API"）。

| 参数 | 说明 |
| ---- | ---- |
| `key` | API Key（与 `x-api-key` 头二选一）。不配置 `API_KEY` 则接口完全公开 |
| `refresh=1` | **强制绕过缓存重新解析**：正结果与负结果都不读，解析后覆盖写回。永久缓存下这是唯一的更新手段。该响应带 `Cache-Control: no-store`，不会被 CDN 缓存 |
| `debug=1` | 返回解析中间状态（路由判定、候选站点、源站命中、搜索尝试片段与命中数、回链校验、耗时分解、`backend`）。**无条件生效**，不需要任何环境变量开关；响应同样 `no-store` |
| `no_preview=1` | 只要元数据、跳过预告片解析（批量列表场景提速用） |
| `quality=720p` | 覆盖本档请求的预告片清晰度偏好 |
| `code` / `codes` | 单个番号（`/api?code=` 或路径 `/:code`）或逗号分隔的番号列表（`/batch?codes=`） |

> `refresh=1` 与 `debug=1` 都能用在 `/batch` 上（`refresh` 会让整批都重新解析）。

## 2. 单条响应

```json
{
  "code": "HEYZO-3953",
  "class": "uncensored",
  "title": "ダイナマイトボディとエロそうな顔立ちがソソるセクシーな微熟女のカレンさん。そんなカレンさんを味わい尽くすべく…",
  "short_title": "ナイスバディな熟美女と濃密4P",
  "cover_url": "https://images.d2pass.com/images/meta/movies/flash/226138.webp",
  "cover_url_alt": "https://www.heyzo.com/contents/3000/3953/images/1.jpg",
  "preview_url": "https://smovie.caribbeancom.com/sample/movies/100526-001/480p.mp4",
  "preview_type": "mp4",
  "preview_quality": "480p",
  "actress": "黛カレン",
  "release_date": null,
  "site_id": "heyzo",
  "site_name": "HEYZO",
  "source_url": "https://www.heyzo.com/moviepages/3953/index.html",
  "d2pass_url": "https://www.d2pass.com/product/movies/226138",
  "match": "backlink",
  "cached": false
}
```

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| code | String | 归一化后的番号（大写；**保留原分隔符**） |
| **class** | String | 有码/无码识别结果：`uncensored` / `censored` / `amateur` / `unknown`。调用方用它决定走哪个源（无码→本服务，有码→DMM/FALENO，素人→FC2） |
| **title** | String | **剧情介绍（长文）** |
| **short_title** | String | **标题（作品名，短）** |
| cover_url | String | 封面，默认 D2Pass 的 webp |
| cover_url_alt | String | 源站封面（兜底；D2Pass 未上架时用它） |
| **preview_url** | String | **预告片直链**（字段名对齐 DMM 源的 `preview_url`）；拿不到为 null |
| **preview_type** | String | `mp4`（默认）或 `hls`（Hey動画备选源用 m3u8） |
| **preview_quality** | String | 实际命中的档位：`480p` / `360p` / `240p` / `720p` / `1080p` / `single`（单档站） |
| actress | String | 出演者，多人用 `、` 连接；**名字里的空格属于名字本身**（如 0930 系的「船井 悠佳」），调用方不要按空格切分。拿不到为 null |
| release_date | String | 发行日，**不归一化**（`2024-09-10` / `2026/10/04` / `2026年8月26日` 都可能）。拿不到为 null |
| site_id / site_name | String | 命中的加盟站（`heyzo` / `HEYZO`） |
| source_url | String | 源站详情页（已强制 https） |
| d2pass_url | String | D2Pass 商品页；未在 D2Pass 上架时为 null |
| match | String | 命中方式：`exact` / `backlink` / `fuzzy` |
| cached | Boolean | 本次是否命中缓存 |

> `short_title` 里的敏感字（源站打码为 ●、■）原样返回，不还原。

**字段口径与 DMM 源完全一致**：`short_title` = **标题**（作品名，短），`title` = **剧情介绍**（长文）。扩展侧 `TrailerPreview.tsx` 的渲染逻辑不用改：`displayShortTitle ← short_title`、`displayLongTitle ← title`。

## 3. 批量响应

```json
{
  "results": {
    "HEYZO-3953": { "...": "同单条" },
    "100426-001": { "...": "同单条" }
  },
  "errors": {
    "XXX-000": { "code": 40401, "error": "ITEM_NOT_FOUND", "message": "..." }
  },
  "cached": { "HEYZO-3953": true, "100426-001": false }
}
```

**部分成功语义**：单个番号失败不影响其他番号，HTTP 状态固定 200；调用方按 `errors` 逐条判定。
单次批量上限 50 个番号，超过返回 400 `TOO_MANY_CODES`。

## 4. 错误码

复用 DMM 源的编号体系，客户端可共用一份错误处理：

| HTTP | code | error | 原因 |
| ---- | ---- | ----- | ---- |
| 400 | 40001 | MISSING_CODE | 缺少番号参数 |
| 400 | 40002 | INVALID_CODE | 番号格式无法归一化 |
| 400 | 40003 | TOO_MANY_CODES | 批量查询超过 50 个 |
| 401 | 40101 | MISSING_API_KEY | 缺少 API Key |
| 403 | 40301 | INVALID_API_KEY | API Key 错误 |
| 404 | 40401 | ITEM_NOT_FOUND | 番号不存在（源站查无 + D2Pass 无匹配） |
| 429 | 42901 | RATE_LIMITED | 触发限流 |
| 500 | 50001 | INTERNAL_SERVER_ERROR | 服务内部错误 |
| 503 | 50301 | SOURCE_UNAVAILABLE | 源站**无法定性**：超时 / 网络错误 / 5xx / 地域拦截。响应带 `Retry-After: 5`，且**不写任何缓存** |

### 4.1 `404` 与 `503` 必须区分（调用方须知）

- `404 ITEM_NOT_FOUND` = **确认**查无，可安全当作"不存在"。
- `503 SOURCE_UNAVAILABLE` = **暂时无法定性**（超时/5xx/被拦截）。客户端遇到 `503` 应当按 `Retry-After` 秒后**重试**，**不要**当作"不存在"落库。

> 详细的设计理由（为何不能把 `503` 报成 `404`、为何不能退到分隔符兄弟形态）见内部文档「解析流水线与踩坑」。

### 4.2 早退规则（无关番号不进缓存）

**本服务只承接无码番号。** 有码号（`IPX-118`）、素人号（`FC2-*` / `SIRO-*`）、乱码都在读缓存/写缓存/限流之前就被拒绝，返回 `404 ITEM_NOT_FOUND`，并额外带一个 `class` 字段便于调用方分流：

```json
{ "code": 40401, "error": "ITEM_NOT_FOUND", "message": "...", "class": "censored" }
```

| 传入 | class | 行为 |
| ---- | ----- | ---- |
| `IPX-118`、`SSIS-001`、`QQQ-000` | `censored` | 就地 404：**零 Redis 命令、零上游请求** |
| `FC2-3061625`、`SIRO-4567` | `amateur` | 同上 |
| `ZZZZZ` 之类乱码 | `unknown` | 同上 |
| `HEYZO-3949`（无码但源站查无） | — | 会真去源站探测，并写负结果键（6h） |

> `QQQ-000` 这种"字母+连字符+数字"的形状与有码番号无法区分，按 `censored` 归类（有码数量占绝对多数，是安全默认）。

## 5. 缓存行为（调用方视角）

- **正结果永久保存**（不设过期）：作品信息基本不变，冷启动成本只付一次。
- **负结果（"没查到"）默认 6 小时后过期**：一次偶发失败不该把番号永久判死；6 小时后自动重试上游。
- **`refresh=1` 是唯一的强制更新手段**：绕过正负缓存重新解析并覆盖写回。
- **CDN 缓存**：元数据 `Cache-Control: public, s-maxage=86400, stale-while-revalidate=604800`；`refresh=1` / `debug=1` / `no_preview=1` / 带 `quality=` 时改 `no-store`，不进 CDN。
- **媒体（mp4/m3u8）不经过本服务的 CDN**，由调用方直连源站。
- Redis 不可用时自动退化为进程内缓存，接口仍可用（只是每个实例各存一份）。

> 缓存键只有番号。带 `no_preview=1` 存的残缺条目、带 `quality=` 的覆盖结果，与主口径结果互不可复用——否则会污染永久缓存。具体隔离规则见内部文档「缓存内部设计」。

## 6. 调用示例

```bash
BASE="https://你的部署域名"

# 单条查询（带 key）
curl -s "$BASE/HEYZO-3953?key=YOUR_KEY"

# 等价写法
curl -s "$BASE/api?code=HEYZO-3953&key=YOUR_KEY"

# 批量查询
curl -s "$BASE/batch?codes=HEYZO-3953,100126-100,QQQ-000&key=YOUR_KEY"

# 强制刷新（绕过缓存重解析）
curl -s "$BASE/HEYZO-3953?key=YOUR_KEY&refresh=1"

# 调试：返回解析中间状态（无条件生效，但仍需 key）
curl -s "$BASE/HEYZO-3953?key=YOUR_KEY&debug=1"

# 不带 key → 401 MISSING_API_KEY
curl -s "$BASE/HEYZO-3953"
```
