# advanced（进阶内容 · 可选部署）

本目录是扩展的**三个可选后端服务**。它们不是扩展的运行前提——**不部署任何一项，扩展依然可以正常使用**：番号识别、标注、Emby 联动、设置同步、页面预览等核心能力全部在扩展内部完成，不依赖这些服务。

> ## ⚠️ 重要：dmm-api 与 d2pass-api「必须日本出口」才能正常工作
>
> 这两个服务（Vercel Node Function）本质是你自建的**反向代理**：服务端从日本出口去抓 DMM / FALENO / 18 家无码站，再回传标题、封面、预告片直链。**没有日本出口，它们就工作不正常**，有两条硬约束：
>
> 1. **部署必须落在东京区域（`hnd1`）**——DMM 拦截**非日本**出口、FALENO 拦截**大陆段**（大陆宽带一律 403，美国 / 东京出口可用）、无码站多数解析失败。`hnd1` 同时满足三者。dmm-api 由 `vercel.json` 锁死 `hnd1`；d2pass-api 需在 Dashboard 设 `serverlessFunctionRegion=Tokyo`（它用显式 `builds`，带不了 `regions`）。
> 2. **接口返回的封面图 / 预告片仍是源站直链**（如 `pics.dmm.co.jp`、`cc3001.dmm.co.jp`、各无码站 CDN）。浏览器加载这些直链**同样需要日本 IP**。也就是说：反代部署在日本，只解决了「查询」；**大陆 / 非日本节点的浏览器，仍可能因为加载不了封面 / 视频直链而看到裂图、黑屏**，除非浏览器侧本身能访问日本源站，或你额外部署了「媒体代理」把图片 / 视频也拐到日本出口转发。
>
> **简言之：配置反代 ≠ 非日本网络就能直接看到封面和视频。** 非日本用户体验通常是「番号能查到标题，但封面 / 视频加载不出来」。要彻底解决，需让客户端走日本节点，或另配媒体代理。（deepl-translate-api 是 Cloudflare Worker，不在此列。）

部署它们只是为了让少数体验更好或可用：

| 服务 | 解决什么问题 | 不部署的后果 | 平台 |
| --- | --- | --- | --- |
| [`dmm-api/`](./dmm-api/) | DMM / FALENO 番号的封面与预告片查询，附带元数据兜底 | **DMM 整源不可用**（必须日本出口）；FALENO 改为浏览器直连 `faleno.jp`（大陆宽带 403，非大陆出口可用） | Vercel（Node Function） |
| [`d2pass-api/`](./d2pass-api/) | 18 家无码站的番号 → 标题 / 封面 / 预告片 / 商品页 | 这些站点没有预览，只有番号识别与标注 | Vercel（Node Function） |
| [`deepl-translate-api/`](./deepl-translate-api/) | 页面整段翻译（DeepL 代理 + 永久缓存） | 翻译功能不可用或需自备其它翻译接口 | Cloudflare Workers |

三者互相独立，可以只部署其中一个。它们之间也**不需要**互相调用。

## 目录

```
advanced/
├── adaptive-proxy.js        通用边缘反代（Cloudflare Worker）：把请求原样转发到某个上游域名
├── dmm-api/                 dmm-api 后端（含云函数与部署文档）
├── d2pass-api/              d2pass-api 后端（含云函数与部署文档）
└── deepl-translate-api/     DeepL 翻译 Worker
```

`adaptive-proxy.js` 是给国内网络环境准备的可选入口：当 `*.vercel.app` 直连不理想时，用它套一层自有域名。上游地址由环境变量 `DOMAIN` 驱动，**与具体服务无关**，谁都可以用同一份脚本转发到自己的域名。

## 关于凭据与部署目标

本目录下所有文档（`README.md`、`部署指南.md`、`接口文档.md`）都**只写占位符**：不包含任何真实密钥、账号、项目名或域名。原因很简单——文档是要给其他部署者看的，写死某台机器的信息既无意义也不安全。

你自己部署时需要的东西请放在**不入库**的私有文件里，例如 `advanced/SECRETS.local.md`（本仓库 `.gitignore` 已通过 `secrets.local.*` 排除）。建议至少记录：

- 各服务的 API Key / 部署 token
- 实际部署到的项目名、区域、域名
- 该项目的环境变量清单

这样"照着文档部署"和"管理自己那份实例"是两件事，互不污染。

## 部署前请先确认一件事

这三个服务都是**抓取公开网页**再返回结构化数据。自行部署意味着：

1. **合规风险由部署者承担**——所在地区对目标站点、内容类型、爬取行为的法律规定各不相同；
2. **平台条款要自己看一眼**——例如 Vercel 的 Hobby 档限非商业用途，且 AUP 对爬虫类负载有明确限制；
3. **部署者自己的账号额度会被消耗**——函数调用、带宽、KV/Redis 用量都记在你的账号上。

如果不确定，**不部署就是完全合法的默认选择**：扩展的核心功能不受影响。
