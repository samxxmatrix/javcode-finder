# DeepL Translation API 接口文档

> 本文只写占位符：不含任何真实密钥、Worker 名或域名。你自己的值请放在不入库的私有文件里，并用 `npx wrangler secret put` 注入 Worker。

## 基本信息

**Base URL**

```
https://<your-worker-domain>/
```

所有 API 请求都必须携带：

```
Authorization: Bearer YOUR_CLIENT_API_KEY
```

未携带或 Key 错误时：

```json
{
  "success": false,
  "error": "Unauthorized"
}
```

## 接口列表

| 方法 | 接口 | 需要 Key | 用途 |
| ---- | ---- | -------- | ---- |
| GET | / | ✅ | 根路径 |
| GET | /health | ✅ | 服务状态 |
| GET | /usage | ✅ | DeepL 用量 |
| POST | /translate | ✅ | 文本翻译 |

注意：根路径 `/` 不会公开 API 信息，也必须经过 Key 验证。

## 身份认证

所有接口都使用 Bearer Token。

请求头：

```
Authorization: Bearer YOUR_CLIENT_API_KEY
```

例如：

```
Authorization: Bearer abc123456789
```

其中 `YOUR_CLIENT_API_KEY` 就是 Worker 上配置的 `CLIENT_API_KEY` 变量的值。

## GET /

用于测试 Worker 是否可以访问。

**请求**

```http
GET /
Authorization: Bearer YOUR_CLIENT_API_KEY
```

**成功响应**

```json
{
  "success": false,
  "error": "Not Found"
}
```

当前版本不会返回 API 信息。

如果不带 Key：

```json
{
  "success": false,
  "error": "Unauthorized"
}
```

## GET /health

检查 Worker 是否正常运行。

**请求**

```http
GET /health
Authorization: Bearer YOUR_CLIENT_API_KEY
```

**成功响应**

```json
{
  "success": true,
  "status": "ok"
}
```

**未授权**

```json
{
  "success": false,
  "error": "Unauthorized"
}
```

## GET /usage

查询 DeepL API 当前累计字符使用情况。

**请求**

```http
GET /usage
Authorization: Bearer YOUR_CLIENT_API_KEY
```

**成功响应**

```json
{
  "success": true,
  "usage": {
    "character_count": 123456,
    "character_limit": 1000000,
    "remaining_characters": 876544,
    "used_percent": 12.35
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| character_count | Number | 已使用字符数 |
| character_limit | Number | 当前 DeepL 字符额度 |
| remaining_characters | Number | 剩余字符 |
| used_percent | Number | 已使用百分比 |

## POST /translate

核心翻译接口。

**请求地址**

```
POST BaseURL/translate
```

**Headers**

```
Authorization: Bearer YOUR_CLIENT_API_KEY
Content-Type: application/json
```

### 最简单的请求

```json
{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
```

**完整请求**

```http
POST /translate HTTP/1.1
Host: BaseURL
Authorization: Bearer YOUR_CLIENT_API_KEY
Content-Type: application/json

{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
```

**返回**

```json
{
  "success": true,
  "translation": "你好，世界",
  "detected_source_language": "EN",
  "target_language": "ZH",
  "usage": {
    "input_characters": 11,
    "chunks": 1
  },
  "provider": "deepl",
  "cached": false
}
```

### 请求参数

**text**

主要文本参数，类型 String，必填。

```json
{
  "text": "Hello world"
}
```

**input**

为了兼容部分 OpenAI 风格请求，也支持：

```json
{
  "input": "Hello world",
  "target": "zh-CN"
}
```

等价于：

```json
{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
```

**q**

同时兼容 Google Translate 风格：

```json
{
  "q": "Hello world",
  "target": "zh-CN"
}
```

## 目标语言

支持：

```json
{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
```

也可以：

```json
{
  "text": "Hello world",
  "target": "zh"
}
```

当前代码会自动转换成 DeepL 使用的语言代码。

常用示例：

| 输入 | DeepL |
| ---- | ----- |
| zh | ZH |
| zh-CN | ZH |
| zh-TW | ZH-HANT |
| en | EN-US |
| en-US | EN-US |
| en-GB | EN-GB |
| ja | JA |
| ko | KO |
| de | DE |
| fr | FR |
| es | ES |
| it | IT |
| ru | RU |

也可以直接传 DeepL 语言代码，例如：

```json
{
  "text": "こんにちは",
  "target_lang": "EN-US"
}
```

## 源语言

默认情况下不指定源语言，由 DeepL 自动检测。

例如：

```json
{
  "text": "こんにちは",
  "target_lang": "zh-CN"
}
```

也可以手动指定：

```json
{
  "text": "こんにちは",
  "source_lang": "JA",
  "target_lang": "zh-CN"
}
```

同时支持：

```json
{
  "text": "こんにちは",
  "source": "JA",
  "target": "zh-CN"
}
```

## OpenAI/Google 风格兼容

接口目前支持三种文本字段：

**标准**

```json
{
  "text": "Hello world",
  "target_lang": "zh-CN"
}
```

**OpenAI 风格**

```json
{
  "input": "Hello world",
  "target": "zh-CN"
}
```

**Google 风格**

```json
{
  "q": "Hello world",
  "target": "zh-CN"
}
```

不过需要注意：这只是请求参数兼容，并不是完整兼容 OpenAI `/v1/chat/completions` 或 Google Translation API 的完整协议。

## 长文本自动分段

接口最大接受 50,000 字符（`MAX_INPUT_CHARS = 50000`）。

例如：

```json
{
  "text": "这里是一大段很长的文本……",
  "target_lang": "zh-CN"
}
```

Worker 会自动：

```text
50,000 字符以内
        ↓
按段落分割
        ↓
按句子分割
        ↓
单段约 4,000 字符
        ↓
逐段发送 DeepL
        ↓
重新合并
        ↓
返回完整翻译
```

因此客户端不需要自己把长文本拆开。

## 缓存

翻译结果会使用 Cloudflare Workers KV 永久保存。

第一次请求：

```text
Hello world
      ↓
DeepL
      ↓
翻译
      ↓
KV 永久保存
```

第二次请求相同文本：

```text
Hello world
      ↓
KV
      ↓
直接返回
```

返回结果中的 `"cached": false` 表示本次没有命中缓存；命中则为 `"cached": true`。

注意：KV 是持久存储，写入后不会自动过期，同一文本的翻译结果会一直复用。如需清除某条记录，需在 Cloudflare 控制台的 KV 中删除对应 Key。

## 缓存判断

缓存 Key 根据以下内容生成：

```text
文本
+
目标语言
+
源语言
```

所以：

```json
{
  "text": "Hello",
  "target_lang": "zh-CN"
}
```

和：

```json
{
  "text": "Hello",
  "target_lang": "ja"
}
```

不会共用缓存。

同样：

```json
{
  "text": "Hello",
  "target_lang": "zh-CN",
  "source_lang": "EN"
}
```

和：

```json
{
  "text": "Hello",
  "target_lang": "zh-CN"
}
```

也是不同缓存。

## 错误响应

### DeepL 限流

HTTP `429 Too Many Requests` 时，Worker 会自动重试，最多 3 次。

### 统一错误格式

```json
{
  "success": false,
  "code": "ERROR_CODE",
  "error": "简洁错误原因"
}
```

例如：

```json
{
  "success": false,
  "code": "AUTH_INVALID",
  "error": "访问密钥无效"
}
```

### 错误码表

| HTTP | 错误码 | 错误原因 |
| ---- | ------ | -------- |
| 401 | AUTH_REQUIRED | 缺少访问密钥 |
| 401 | AUTH_INVALID | 访问密钥无效 |
| 503 | AUTH_CONFIG_MISSING | 服务密钥未配置 |
| 503 | CONFIG_DEEPL_KEY_MISSING | DeepL 密钥未配置 |
| 400 | INVALID_JSON | JSON 格式无效 |
| 400 | INVALID_TEXT | text 必须为字符串 |
| 400 | EMPTY_TEXT | 文本不能为空 |
| 413 | INPUT_TOO_LONG | 输入文本过长 |
| 400 | DEEPL_BAD_REQUEST | DeepL 请求无效 |
| 401 | DEEPL_AUTH_FAILED | DeepL 密钥无效 |
| 403 | DEEPL_FORBIDDEN | DeepL 访问被拒绝 |
| 404 | DEEPL_NOT_FOUND | DeepL 接口不存在 |
| 429 | DEEPL_RATE_LIMIT | DeepL 请求过于频繁 |
| 456 | DEEPL_QUOTA_EXCEEDED | DeepL 配额已用尽 |
| 502 | DEEPL_CONNECTION_FAILED | 无法连接 DeepL |
| 502 | DEEPL_RESPONSE_INVALID | DeepL 响应无效 |
| 502 | DEEPL_NO_TRANSLATION | DeepL 未返回翻译 |
| 500/502 | DEEPL_SERVER_ERROR | DeepL 服务异常 |
| 502 | USAGE_FAILED | 无法获取 DeepL 用量 |
| 500 | INTERNAL_ERROR | 服务内部错误 |
| 404 | NOT_FOUND | 接口不存在 |
## 部署

架构：单个 Cloudflare Worker，无后端服务、无构建步骤。

**本文不记录任何具体实例信息**（Worker 名、域名、KV id 都属于部署者自己的账号）。从零部署的完整步骤见 [`部署指南.md`](./部署指南.md)，要点：

1. 创建 KV namespace，binding 名必须是 `DEEPL_KV`；
2. `wrangler.toml` 填自己的 Worker 名与 KV id（该文件含账号侧信息，不入库）；
3. `npx wrangler secret put DEEPL_API_KEY` 与 `CLIENT_API_KEY`；
4. `npx wrangler deploy`；
5. 用 `GET /health` 带 Bearer 验证。

上面的 Base URL 请替换成你自己部署后的域名。
