# deepl-translate-api 部署指南（Cloudflare Workers）

把一个单文件 Worker 部署到**你自己的** Cloudflare 账号，作为 DeepL 的带缓存代理。接口契约见 [`接口文档.md`](./接口文档.md)。

> 本文只写占位符。密钥、Worker 名、域名请自行保管在**不入库**的文件里（例如 `advanced/SECRETS.local.md`），不要写进会提交的任何东西。

## 0. 部署形态

| 项 | 值 |
| --- | --- |
| 平台 | Cloudflare Workers（免费档可用） |
| 产物 | 单个 Worker，无构建步骤、无 npm 依赖 |
| 状态 | Workers KV（一个 namespace，存翻译结果） |
| 密钥 | 两个变量：`DEEPL_API_KEY`、`CLIENT_API_KEY` |
| 首次耗时 | 约 10 分钟（含注册 DeepL、建 KV、注入密钥） |

**成本**：Workers 免费档每天 10 万次请求；KV 免费档每天 10 万次读、1000 次写。翻译结果永久缓存会把写入压到很低，通常不会触顶。

## 1. 前置条件

1. **Cloudflare 账号**（免费即可）。
2. **DeepL API Key**：注册 [DeepL API Free](https://www.deepl.com/pro-api)（免费版每月 50 万字符）。Key 形如 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx:fx`，**结尾的 `:fx` 是免费版标志**。
3. **Node.js 18+**（只为跑 `wrangler`，它不参与运行）。
4. 一个自己生成的客户端 Key（例如 `openssl rand -hex 24`），用来保护你的 Worker 不被别人白用。

> 如果你用的是 DeepL **Pro**（Key 不带 `:fx`），必须改代码：文件开头 `DEEPL_API_URL` 与 `DEEPL_USAGE_URL` 里的 `api-free.deepl.com` 改成 `api.deepl.com`，否则所有请求都会 403。

## 2. 创建 KV namespace

翻译缓存必须有一个 KV。

```bash
cd advanced/deepl-translate-api
npx wrangler kv namespace create DEEPL_KV
```

命令会打印一个 id，形如：

```
[[kv_namespaces]]
binding = "DEEPL_KV"
id = "<32 位十六进制>"
```

**把这个 id 记下来**，下一步要用。也可以去 Dashboard → Workers & Pages → KV 里建，效果一样。

## 3. 写配置

复制模板并填入自己的值：

```bash
cp wrangler.toml.example wrangler.toml
```

`wrangler.toml` 关键字段：

```toml
name = "<你的 worker 名>"
main = "deepl-translate-api.js"
compatibility_date = "2026-09-26"

[[kv_namespaces]]
binding = "DEEPL_KV"
id = "<上一步的 id>"

[vars]
# 密钥不要写在这里，用 wrangler secret put 注入
```

> **`wrangler.toml` 不要入库**——它含 KV id，属于账号侧信息。本仓库 `.gitignore` 已通过 `wrangler.toml` / `**/wrangler.toml` 排除，入库的只有 `wrangler.toml.example` 模板。
>
> ⚠️ 不要图省事把密钥直接写进 `[vars]` 再提交：那是明文，一旦 push 就等于公开。

## 4. 注入密钥

```bash
npx wrangler login
npx wrangler secret put DEEPL_API_KEY     # 粘贴 DeepL 的 key（带 :fx）
npx wrangler secret put CLIENT_API_KEY    # 粘贴你自己生成的随机串
```

`secret put` 写入的是加密存储，`wrangler.toml` 里不会出现值，Dashboard 里也只显示 `Encrypted`。

> `CLIENT_API_KEY` 不配也能跑，但代码会走"未配置"分支——**等于接口敞开**，任何人拿到你的 Worker 域名都能白用你的 DeepL 额度。务必配置。

## 5. 部署

```bash
npx wrangler deploy
```

输出会给出 Worker 地址，形如 `https://<worker 名>.<你的子域>.workers.dev`。

之后每次改代码，重复 `npx wrangler deploy` 即可；绑定与密钥不需要重设。

## 6. 验证

### 6.1 健康检查

```bash
curl.exe -s "https://<你的域名>/health" -H "Authorization: Bearer <CLIENT_API_KEY>"
```

期望 `{"success":true,"status":"ok"}`。

不带 Authorization 再打一次，期望 `{"success":false,"error":"Unauthorized"}`。**这一步很重要**——如果没带 Key 也能成功，说明 `CLIENT_API_KEY` 没生效。

### 6.2 DeepL 连通性

```bash
curl.exe -s "https://<你的域名>/usage" -H "Authorization: Bearer <CLIENT_API_KEY>"
```

能返回用量说明 DeepL Key 有效。这里 403 通常是：用了 Pro 账号但代码还指着免费端点，或 Key 复制时带了空格。

### 6.3 翻译

```bash
curl.exe -s -X POST "https://<你的域名>/translate" ^
  -H "Authorization: Bearer <CLIENT_API_KEY>" ^
  -H "Content-Type: application/json" ^
  -d "{\"text\":\"Hello world\",\"target_lang\":\"zh\"}"
```

期望返回中文译文。

### 6.4 缓存生效

同样的请求再打一次。第二次应当明显更快，且**不再消耗 DeepL 额度**（对比两次 `/usage` 的 `character_count` 即可确认）。

## 7. 绑定自定义域名（可选）

`*.workers.dev` 在国内访问通常不理想。Dashboard → Workers & Pages → 你的 Worker → **Settings → Domains & Routes → Add custom domain**，填一个你已托管在 Cloudflare 的域名，按提示加解析即可。

配好后扩展里填这个自定义域名。

## 8. 排查表

| 现象 | 原因与处理 |
| --- | --- |
| 所有请求 `Unauthorized` | 没带 `Authorization: Bearer …`，或 `CLIENT_API_KEY` 不一致（注意首尾空格） |
| `/usage` 或 `/translate` 返回 403 | ① DeepL Key 无效或已过期 ② Pro 账号却用了 `api-free` 端点（见第 1 节）③ Key 复制时带入空格 |
| 456 / 配额错误 | DeepL 免费额度用尽，等下月或升级套餐 |
| 429 | 触发 DeepL 限流。Worker 会自动退避重试 3 次；仍失败说明并发过高 |
| 翻译不缓存、每次都变慢 | KV 绑定名不是 `DEEPL_KV`，或 `wrangler.toml` 的 `[[kv_namespaces]]` 未生效（重新 `deploy` 时看输出有没有绑定） |
| 部署报 `No such namespace` | `id` 填错或填的是别的账号的 namespace |
| 长文本报错 | 单次请求上限 50000 字符；超出请在客户端自行分段 |
| 中文目标语言不对 | `zh` → 简体，`zh-TW` → 繁体；大小写不敏感 |

看日志：Dashboard → Worker → **Logs**（实时 tail），或 `npx wrangler tail`。

## 9. 更新与回滚

| 操作 | 命令 |
| --- | --- |
| 改了代码重新上线 | `npx wrangler deploy` |
| 改密钥 | `npx wrangler secret put <名字>` |
| 本地预览 | `npx wrangler dev` |
| 看部署历史 / 回滚 | Dashboard → Worker → Deployments → 选历史版本 → Rollback |
| 换 KV | 改 `wrangler.toml` 的 id 后重新 deploy（旧缓存放着不影响） |

## 10. 安全

1. **必须配 `CLIENT_API_KEY`**，否则接口敞开，别人能用你的 DeepL 额度。
2. **密钥只走 `secret put`**，不要写进 `wrangler.toml` 的 `[vars]`，更不要提交。
3. **`wrangler.toml` 不入库**（含 KV id）。换机器前记得备份，丢了就得去 Dashboard 重新取 id 并重建配置。
4. **翻译内容是明文经过 Cloudflare 与 DeepL 的**。介意内容隐私就不要用第三方翻译接口。
