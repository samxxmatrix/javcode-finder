# javcode-api 部署指南

> ⚠️ **重要前提：部署并接入扩展后，需要日本出口代理才能正常使用**
>
> javcode-api 部署完成、并在扩展里接入后，要**正常使用**（看到封面、预告片等增强数据），你的浏览器 / 网络必须走**日本出口代理（Japan exit proxy）**。
>
> **原因**：服务返回的是日本源站（DMM / FALENO / 各家无码站）的**直链**，封面图与预告片由你的浏览器**直接从这些源站加载**。这些源站对**非日本出口**有拦截——没有日本出口时，查询能成功、但图片/视频会加载失败（裂图、黑屏、无法播放）。
>
> 这与服务是否部署在东京 `hnd1` **无关**：服务端在东京负责「查」，但「看」的媒体流量从你的本地网络走。请**提前准备好可用的日本出口代理**，再部署并接入使用。

本指南写给**需要自行部署一份 `javcode-api`** 的人。目标很明确：拿到一个**服务地址**和一个 **API Key**，填进扩展的「设置 → 进阶设置 → 数据源 → 番号查询」，打开开关即可。

下面给出两种部署方式（**CLI 部署** 与 **Vercel 控制台部署**），每一步都写清楚；随后是缓存配置、自检与接入扩展的步骤。

## 0. 部署前须知

1. **区域被锁死在东京 `hnd1`**。`vercel.json` 已写死，不要在控制台改。原因：DMM 拦非日本出口、FALENO 拦大陆段、多数无码站对非日本解析失败。区域不对 → 大面积查询返回 `503`，不是配置问题。
2. **接口返回的是源站直链，服务端不代理任何图片/视频字节**。`/health` 通过、查询也成功，**不等于**封面和预告片一定能显示——那取决于**你浏览器所在网络能否访问日本源站**（见顶部前提）。这条与部署成败无关，无法靠改区域解决。
3. **合规与成本由你承担**：Vercel Hobby 限非商业用途、AUP 对爬虫类负载有约束；函数调用、带宽、缓存用量都记在你账号上。所在地区对目标站点与爬取行为的法律规定各不相同，先自行确认。

## 1. 部署方式一：CLI（命令行）

适合习惯命令行的使用者，全程本地完成。

### 步骤 1 — 安装并登录 Vercel CLI

```bash
npm install -g vercel
vercel login          # 浏览器打开后授权，选 GitHub / GitLab / Email 任一
```

### 步骤 2 — 进入服务目录

```bash
cd advanced/javcode-api
```

本目录是一个独立 Vercel 项目：唯一函数是 `api/index.js`，`vercel.json` 负责路径重写与区域锁定。

### 步骤 3 — 配置必填环境变量 `API_KEY`

先设环境变量再部署，避免部署后忘记：

```bash
# 生成一个强随机串作为 Key（任选其一）
openssl rand -hex 24
vercel env add API_KEY           # 交互式：类型选 Encrypted，值粘贴上面的随机串，环境选 Production
```

`API_KEY` 是**唯一必填项**。没配它，所有接口返回 `503`，且覆盖 `/health` 在内的全部接口。

> 可选：此时一并把缓存也配上（强烈建议，见第 3 节），例如 `vercel env add REDIS_URL`。

### 步骤 4 — 部署到生产

```bash
vercel deploy --prod
```

首次部署会提示 `Link to existing project?` → 选 `N` 新建，然后按提示设置项目名与团队（scope）。`vercel.json` 会把函数锁到 `hnd1`、`maxDuration: 60`，无需在控制台调整。

### 步骤 5 — 拿到服务地址

部署完成输出形如 `https://javcode-api-xxxx.vercel.app` 的域名，这就是后面要填的**服务地址**。

## 2. 部署方式二：Vercel 控制台（页面部署）

适合不想装 CLI 的使用者，全部在网页上点完。

### 步骤 1 — 导入 Git 仓库

1. 打开 [Vercel Dashboard](https://vercel.com/dashboard)，点 **Add New… → Project**。
2. **Import Git Repository**：先连接你的 GitHub / GitLab 账号，选中托管 `javcode-finder` 的仓库。
3. **Configure Project** 里把 **Root Directory**（根目录）改成 `advanced/javcode-api`（默认是仓库根，必须改，否则找不到 `api/` 与 `vercel.json`）。
4. Framework Preset 选 **Other**，Build Command / Output 留空（由 `vercel.json` 驱动）。

### 步骤 2 — 配置必填环境变量 `API_KEY`

在构建/部署页的 **Environment Variables** 区（或项目建好后 *Settings → Environment Variables*）新增：

| Key | Value | 说明 |
|---|---|---|
| `API_KEY` | 你自己定的强随机串 | **必填**，没它全站 503 |

> 可选：此时一并把 `REDIS_URL` 也加上（强烈建议，见第 3 节）。

### 步骤 3 — 部署

点 **Deploy**。等待构建完成（通常几十秒）。`vercel.json` 会把函数锁到 `hnd1`，无需在控制台改区域。

### 步骤 4 — 拿到服务地址

部署完成后，项目页顶部给出形如 `https://javcode-api-xxxx.vercel.app` 的 **Domains**，这就是后面要填的**服务地址**。

> 不需要为这个服务单独买域名。若 `*.vercel.app` 直连不理想，可再用 `advanced/adaptive-proxy.js`（Cloudflare Worker）套一层自有域名，那属于可选入口层，与部署本服务本身无关。

## 3. 配置缓存 `REDIS_URL`（可选，但强烈建议）

### 为什么强烈建议配

- 本服务**无状态**，缓存**不配也能跑**：未配置时退化为**进程内缓存**（仅单实例内存、重启即清空）。
- 但 Vercel 函数**多实例、随时冷启动**，进程内缓存几乎每次请求都打空 → 大量重复抓取源站、命中率极低、上游压力大、响应也更慢。
- 配置 `REDIS_URL` 后，缓存落在**外部 Redis**，跨实例/重启共享，**命中率高、省上游、响应更快**，也显著降低被源站风控的概率。

**结论：能用 Redis 就一定要配。** 不配不影响功能正确性，但体验与稳定性差很多。

### 配置步骤（在 Vercel 内集成 Upstash for Redis，环境变量自动写入）

1. 在 Vercel 项目中打开 **Storage（存储） → Connect Database（连接数据库）**，在 Upstash 分类下选择 **Upstash for Redis**，点击 **Continue（继续）**。
2. **Primary Region (required)（主区域（必填））** 选择 **Tokyo, Japan (hnd1)**；**Installation Plans（安装方案）** 选择 **Free（免费）**，点击 **Continue（继续）**。
   > 其余选项保持默认或留空即可。
3. 点击 **Create（创建）**，等待创建完成。
4. **Project（项目）** 选择本项目（即 javcode-api），点击 **Connect（连接）** 完成。连接后 Redis 的环境变量（`REDIS_URL` 等）会**自动写入**项目环境变量，无需手动复制。

> 说明：本服务读取 `REDIS_URL`。通过 Vercel 内集成 Upstash 时该变量会自动注入；若个别情况下未自动写入，可手动复制 Upstash 提供的 `REDIS_URL`（形如 `rediss://default:xxxx@xxxx.upstash.io:6379`），到 *Settings（设置） → Environment Variables（环境变量）* 新增 `REDIS_URL` 后 **Redeploy（重新部署）**。也可用 Vercel KV、自托管 Redis 等，只要提供一个 `redis://` 或 `rediss://` 连接串即可，变量名必须是 `REDIS_URL`。

5. 验证生效：部署后跑一次 `/health`（见第 4 节）即可——缓存层不影响健康检查结果；想确认命中可看查询响应的 `cached: true`。

## 4. 自检：就是扩展会替你做的那一步

部署完，用一次 `/health` 验证「服务可达 + Key 正确」同时成立：

```bash
curl "https://<your-project>.vercel.app/health?key=YOUR_API_KEY"
# → {"ok":true,"service":"javcode-api"}
```

`/health` **不查任何番号、不碰源站**，只探活与验 Key。返回含义：

| 返回 | 含义 | 你该怎么做 |
|---|---|---|
| `200` + `{"ok":true,…}` | 服务可用、Key 正确 | 可以接入扩展 |
| `40101` / `40301` | Key 缺失或错误 | 检查 `API_KEY` 环境变量 |
| `503` / `50301` | 服务不可达，或服务端没配 Key | 确认部署成功、环境变量已生效 |

**这一步和扩展「番号查询」开关的行为完全一致**：开关打开时会先请求 `GET /health`，就地区分「密钥无效」与「服务不可达」，不会静默失败。自检通过，意味着扩展侧一定也能通过。建议把自检超时按 8 秒处理。

## 5. 把实例接回扩展

在扩展里：`设置 → 进阶设置 → 数据源 → 番号查询`

1. 填入**服务地址**：`https://<your-project>.vercel.app`
2. 填入 **API Key**：即你部署时设的 `API_KEY`
3. 打开开关 —— 开关会先打 `GET /health`（见第 4 节），通过后才真正启用查询能力

接入后：有码号、FALENO、无码号都能拿到标题、封面、预告片直链；列表与详情页的「在库」标识、预览都更完整。

> 再次提醒顶部前提：**接入后请确认浏览器走日本出口代理**，否则封面/预告片会加载失败。

具体每个接口怎么调、返回什么字段，见 [`接口文档.md`](./接口文档.md)。

## 6. 环境变量速查

只有 `API_KEY` 是必填。其余都有默认值，按需调整——下面按「会不会影响你看到的结果」排序：

| 变量 | 默认 | 必填 | 要不要管 |
|---|---|---|---|
| `API_KEY` | 无 | **是** | 必填，没它全站 503 |
| `REDIS_URL` | 空 | 否（**强烈建议配**） | 配了跨实例/重启共享缓存；不配退化为进程内缓存，命中率极低 |
| `PREVIEW_QUALITY` | `320p` | 否 | **会影响**：预告片清晰度偏好，如想要更清晰设 `480p`/`720p` |
| `PREVIEW_ENABLED` | `true` | 否 | 关掉后所有查询都不解析预告片（更快、更省上游） |
| `BATCH_MAX` | `50` | 否 | 批量单次上限 |
| `RATE_LIMIT_PER_MIN` | `120` | 否 | 仅作用于 `/d2pass`，重度批量时才需要调 |
| `SOURCE_TIMEOUT_MS` / `D2PASS_TIMEOUT_MS` / `TOTAL_BUDGET_MS` / `PROBE_BUDGET_MS` | 见 [`README.md`](./README.md) | 否 | 无码查询偏慢/偏易超时再调，一般不动 |
| `FALENO_ORIGIN` / `DISABLED_SITES` / `SITE_PROXY_<ID>` | 默认 | 否 | 源站换镜像 / 个别站失效时运维用 |

> 最小可用配置就是「只设 `API_KEY`」。但**强烈建议一并配 `REDIS_URL`**（见第 3 节），否则缓存几乎不命中。

## 7. 最常踩的坑

1. **封面/预告片裂图或黑屏**：查询成功、字段也有 `cover_url`/`preview_url`，但那是日本源站直链。你的网络访问不了源站就会加载失败——**这是没有日本出口代理导致的网络问题，不是接口或部署问题**，改区域也没用。请确认浏览器走了日本出口。
2. **区域被改导致大面积 `503`**：在控制台改了函数区域（或误删 `vercel.json` 的 `regions`），源站按出口地区拦截。改回 `hnd1` 即可。
3. **`429` 只来自 `/d2pass`**：无码查询成本最高，限流只作用于它（含批量，但批量整批只计 1 次）。有码查询（`/dmm` 等）不限流。触发限流就按 `Retry-After` 退避。
4. **`404` 与 `503` 含义不同，别混**：`404` = 源站**确认**没有这个番号，重试没意义；`503` = 这次没查成（超时/被 WAF 拦/抖动），**应稍后重试**。详情见 [`接口文档.md` 第 8 节](./接口文档.md)。
5. **没配 `REDIS_URL` 时响应偏慢、上游压力大**：进程内缓存命中率极低，每次都重新抓取。配了 Redis 会明显改善。

## 8. 本地自测（可选）

想先在本地验证，不必上 Vercel：

```bash
cd advanced/javcode-api
npm install
vercel dev          # 按 vercel.json 的 rewrites 起本地服务，路径与线上一致
# 另开一个终端
curl "http://localhost:3000/health?key=YOUR_API_KEY"
curl "http://localhost:3000/dmm/SSIS-001?key=YOUR_API_KEY"
```

`vercel dev` 会套用 `vercel.json` 的重写，因此本地路径与线上完全一致。注意：本地函数默认跑在你本机所在区域，**不满足东京出口**，无码站等可能解析失败——这恰好提醒你线上必须锁 `hnd1`。
