# javcode-api 接口文档

一个自建的番号查询服务：传入番号，返回标题、封面、预告片直链与元数据。服务部署在 Vercel（东京 `hnd1`），由它替你访问 DMM / FALENO / 各家无码站，再把结果整理成统一 JSON。

- 服务地址：`https://<your-project>.vercel.app`（部署后得到，所有接口共用同一域名）
- 传输：HTTPS，GET 请求，响应 `application/json; charset=utf-8`
- 鉴权：**全部接口都需要 API Key**，包括 `/health`

> ⚠️ **重要前提：部署并接入扩展后，需要日本出口代理才能正常使用**
> javcode-api 部署并接入浏览器扩展后，要**正常使用**（看到封面、预告片等增强数据），你的浏览器 / 网络必须走**日本出口代理（Japan exit proxy）**。接口返回的是日本源站（DMM / FALENO / 各家无码站）的**直链**，封面与预告片由浏览器直接从源站加载；这些源站对非日本出口有拦截，没有日本出口时查询能成功、但图片/视频会加载失败。这与服务是否部署在东京无关。详见 [部署指南](./部署指南.md)。

---

## 1. 五分钟接入

```bash
# 1) 探活：一次请求同时验证「服务活着」和「Key 正确」
curl "https://<your-project>.vercel.app/health?key=YOUR_API_KEY"
# → {"ok":true,"service":"javcode-api"}

# 2) 查一个有码番号
curl "https://<your-project>.vercel.app/dmm/SSIS-001?key=YOUR_API_KEY"

# 3) 一次查多个
curl "https://<your-project>.vercel.app/dmm/batch?codes=SSIS-001,IPX-118&key=YOUR_API_KEY"
```

拿到的 `cover_url` 与 `preview_url` 是**源站直链**，可直接交给 `<img>` / `<video>` 使用。本服务只做查询，不代理任何图片或视频字节。

---

## 2. 鉴权

| 项 | 规则 |
|---|---|
| 传递方式 | `?key=YOUR_API_KEY` 或请求头 `x-api-key: YOUR_API_KEY`，二选一，请求头优先 |
| 覆盖范围 | 所有接口，`/health` 也不例外 |
| 没带 Key | `401` / `40101 MISSING_API_KEY` |
| Key 错误 | `403` / `40301 INVALID_API_KEY` |
| 服务端未配置 Key | `503` / `50301`（部署错误，此时所有请求都会被拒绝） |

浏览器跨域带 `x-api-key` 会触发预检，服务端已放行 `OPTIONS` 并返回 204。

---

## 3. 接口一览

| 方法 | 路径 | 用途 | 判成功的字段 |
|---|---|---|---|
| GET | `/health` | 健康检查，同时验证 Key | `ok === true` |
| GET | `/dmm/:code` | 有码番号完整查询 | `cid` |
| GET | `/cid/:code` | 只查商品 ID，最轻量 | `cid` |
| GET | `/faleno/:code` | FALENO 作品页 | `cid` |
| GET | `/dmm/batch?codes=A,B` | 有码批量（≤50） | `results` 内各自的 `cid` |
| GET | `/d2pass/:code` | 无码番号查询 | `code` |
| GET | `/d2pass/batch?codes=A,B` | 无码批量（≤50） | `results` 内各自的 `code` |

> `cid` 与 `code` 两个判成功字段是为兼容两套不同的抓取口径而保留的，调用方按对应接口取用即可。

---

## 4. 健康检查

```
GET /health?key=YOUR_API_KEY
```

| 项 | 值 |
|---|---|
| 成功 | `200` + `{"ok": true, "service": "javcode-api"}` |
| 失败 | `40101`（没带 Key）/ `40301`（Key 错）/ `50301`（服务自身异常） |
| 响应头 | `Cache-Control: no-store` |
| 上游访问 | 无 —— 只探活与验 Key，不查番号、不碰源站 |

它的价值在于**一次请求同时回答两个问题**：服务是否可达、Key 是否正确。客户端在启用查询能力前调用它，就能在界面上直接区分「密钥无效」与「服务不可达」，不必先发一次真实查询再猜错误。

---

## 5. 公共参数

| 参数 | 适用接口 | 说明 |
|---|---|---|
| `key` | 全部 | 必填；与 `x-api-key` 二选一 |
| `codes` | 两个 `/batch` | 逗号分隔，去重后最多 50 个 |
| `refresh=1` | 所有查询 | 绕过缓存重新解析 |
| `debug=1` | 所有查询 | 响应里附带解析中间态（候选站、耗时、错误原因），排查用 |
| `quality=NNNp` | `/dmm`、`/d2pass`（含批量） | 覆盖本次清晰度偏好，如 `480p`；`/cid`、`/faleno` 忽略此参数 |
| `no_preview=1` | `/d2pass`（含批量） | 只要元数据，跳过预告片解析，更快 |

`refresh` / `debug` / `quality` / `no_preview` 都会改变响应内容，服务端对它们一律返回 `Cache-Control: no-store`，不会被中间层缓存吃掉。

---

## 6. 响应字段

### 6.1 `/dmm/:code`

```jsonc
{
  "v": 4,                        // 条目口径版本
  "code": "SSIS-001",            // 查询番号（大写）
  "quality": null,               // 本次生效的 quality 覆盖值
  "cid": "ssis00001",            // DMM 商品 ID —— 以此判定成功
  "channel": "digital",          // digital / mono
  "title": "…（剧情介绍，长文）",
  "short_title": "…（标题，短）",
  "cover_url": "https://awsimgsrc.dmm.co.jp/…/ssis00001pl.jpg",
  "preview_url": "https://cc3001.dmm.co.jp/pv/…/ssis00001_dm_w.mp4",
  "preview_quality": "316p",     // 实际选中的档位
  "preview_qualities": [         // 全部可选档位，按分辨率升序
    { "quality": "180p", "height": 180, "resolution": null, "bandwidth": 300000, "url": "…" }
  ],
  "actresses": ["葵つかさ", "乙白さやか"],
  "delivery_date": "2021-02-18T01:00:00Z",  // 原始抓取值，不归一化
  "sale_date": null,
  "detail_url": "https://www.dmm.co.jp/digital/videoa/-/detail/=/cid=ssis00001/",
  "cached": false                // 是否命中服务端缓存
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `cid` | String | 商品 ID，**判成功字段** |
| `channel` | String | `digital`（数字版）/ `mono`（DVD 版） |
| `title` / `short_title` | String | 剧情介绍 / 标题 |
| `cover_url` | String | 封面大图 |
| `preview_url` | String \| null | 已按偏好选好的预告片 mp4；源站没给则为 null |
| `preview_quality` | String \| null | 实际选中档位 |
| `preview_qualities` | Array | 全部档位表，元素为 `{quality,height,resolution,bandwidth,url}` |
| `quality` | Number \| null | `?quality=` 的覆盖值，参与缓存口径 |
| `actresses` | Array | 出演者名（源站顺序，已拆分去重） |
| `delivery_date` / `sale_date` | String \| null | 配信日 / 发售日，原始值 |
| `detail_url` | String | 详情页 |
| `v` | Number | 条目版本，当前 4。缓存换口径时递增 |
| `cached` | Boolean | 是否命中服务端缓存 |

### 6.2 `/cid/:code`

只返回 `v`、`code`、`quality`、`cid`、`channel`、`cached`。不抓详情页，因此没有标题、封面与预告片 —— 适合只需要「这个号对应哪个商品」的场景。

### 6.3 `/faleno/:code`

字段与 6.1 相同，但**没有** `quality`、`preview_quality`、`preview_qualities`（作品页只有一个 mp4），`channel` 固定为 `"faleno"`。

```jsonc
{
  "v": 4, "code": "FNS-263", "cid": "fns263", "channel": "faleno",
  "title": "…", "short_title": "…",
  "cover_url": "https://cdn.faleno.net/…/FNS-263_1200.jpg?output-quality=60",
  "preview_url": "https://cdn.faleno.net/…/FNS-263_PR.mp4",
  "actresses": ["柏木雫"],
  "delivery_date": "2026/10/2", "sale_date": "2026/11/05",
  "detail_url": "https://faleno.jp/top/works/fns263/",
  "cached": false
}
```

### 6.4 `/d2pass/:code`

```jsonc
{
  "code": "HEYZO-3953",          // 归一化番号（大写，保留分隔符）—— 以此判定成功
  "class": "uncensored",         // uncensored / censored / amateur / unknown
  "title": "…", "short_title": "…",
  "cover_url": "https://…", "cover_url_alt": "https://…",   // 前者优先，后者为源站兜底
  "preview_url": "https://…/sample_low.mp4",
  "preview_type": "mp4",         // mp4 / hls
  "preview_quality": "sample_low",
  "actress": "…",                // 多人用「、」连接
  "release_date": "2024-01-01",
  "site_id": "heyzo", "site_name": "HEYZO",
  "source_url": "https://www.heyzo.com/moviepages/3953/index.html",
  "d2pass_url": "https://…",     // 商品页，可能为 null
  "match": "exact",              // exact / backlink / fuzzy
  "cached": false
}
```

| 字段 | 说明 |
|---|---|
| `code` | **判成功字段**；大小写与分隔符按原番号归一，`HEYZO-3953` 与 `HEYZO_3953` 是不同键 |
| `class` | `censored` / `amateur` / `unknown` 会直接返回 404，不访问源站（本服务只查无码源） |
| `preview_quality` | 可能是像素档（`480p`）或站点自定义标签（`sample_low` / `single` / `hls`） |
| `match` | 命中方式：`exact` 精确、`backlink` 回链校验、`fuzzy` 模糊 |

## 7. 批量

```
GET /dmm/batch?codes=SSIS-001,IPX-118&key=YOUR_API_KEY
GET /d2pass/batch?codes=SIRO-4980,SSIS-001&key=YOUR_API_KEY
```

```jsonc
{
  "results": { "SSIS-001": { /* 与单条查询完全相同的结构 */ } },
  "errors":  { "IPX-118": { "status": 503, "code": 50301, "error": "SOURCE_UNAVAILABLE", "message": "…" } },
  "cached":  { "SSIS-001": true, "IPX-118": false }
}
```

| 项 | 规则 |
|---|---|
| 上限 | 去重后 50 个，超出返回 `400 / 40003 TOO_MANY_CODES` |
| HTTP 状态 | **固定 200**，部分成功：一个号失败不影响其他号 |
| 判定 | 逐条看 `results` / `errors`，不要用整批 HTTP 状态判断成败 |
| `refresh=1` | 对该批全部番号生效 |
| `quality=` | 对该批统一生效 |
| 早退 | D2PASS 批量里非无码形态的番号直接进 `errors`，不访问源站、不计限流 |

批量比逐条请求更省：D2PASS 批量**整批只计 1 次限流**，与 `codes` 数量无关。

## 8. 错误码

| HTTP | code | error | 原因 |
|---|---|---|---|
| 400 | 40001 | `MISSING_CODE` | 缺少番号，或 `codes` 为空 |
| 400 | 40002 | `INVALID_CODE` | 番号无法归一化成已知格式 |
| 400 | 40003 | `TOO_MANY_CODES` | 批量超过 50 个 |
| 401 | 40101 | `MISSING_API_KEY` | 没带 Key |
| 403 | 40301 | `INVALID_API_KEY` | Key 错误 |
| 404 | 40401 | `ITEM_NOT_FOUND` | 确认查无此番号 |
| 429 | 42901 | `RATE_LIMITED` | 触发限流（仅 `/d2pass`） |
| 500 | 50001 | `INTERNAL_SERVER_ERROR` | 服务内部错误 |
| 503 | 50301 | `SOURCE_UNAVAILABLE` | 上游查不动：超时、网络错误、被 WAF 拦截，或服务端未配置 Key |

响应体统一为：

```jsonc
{ "code": 40401, "error": "ITEM_NOT_FOUND", "message": "Item not found for the requested code." }
```

**404 与 503 必须区别对待**：

- `404` = **确认**源站没有这个番号，重试没有意义。
- `503` = 这次没查成，**可能只是源站抖动或被拦截**，应稍后重试；响应带 `Retry-After: 5`。

特别地，源站返回 403 / 429（地区拦截、风控限流）会被译成 `503` 而不是 `404` —— 否则调用方与用户都会误以为片子不存在。`debug=1` 时可在 `siteError` 里看到 `source blocked: <host> (403)`。

## 9. 缓存与响应头

| 场景 | `Cache-Control` |
|---|---|
| `/d2pass` 及其批量（成功） | `public, s-maxage=86400, stale-while-revalidate=604800` |
| `/dmm`、`/cid`、`/faleno` 及其批量（成功） | 不设置（避免 CDN 吃掉 `refresh=1` 与 `quality=`） |
| 带 `refresh` / `debug` / `quality` / `no_preview` | `no-store` |
| `/health`、任何错误 | `no-store` |

服务端缓存（可选，需配置 `REDIS_URL`，未配置时退化为进程内缓存，不影响功能）：

| 分支 | 键 | 有效期 |
|---|---|---|
| DMM | 裸番号 / `CID:` / `FALENO:` | 资料齐全永久、资料不全 6 小时 |
| D2PASS | `D2P:` | 永久（命中即可复用，源站补数据需 `refresh=1`） |
| D2PASS 负缓存 | `D2P:NF:` | 6 小时 |
| 限流计数 | `D2P:RL:` | 60 秒固定窗口 |

调用方命中缓存时会看到 `cached: true`。想拿最新数据就带 `refresh=1`。

---

## 10. 限流

只作用于 `/d2pass`（单查与批量都算，批量整批计 1 次），默认 **120 次/分钟**，按 API Key 或来源 IP 计数，超出返回 `429 / 42901`。固定窗口，每分钟重置。

`/dmm`、`/cid`、`/faleno` 不限流。

---

## 11. 调用约定

1. **传原始番号，不要替服务端归一化**。服务端两套缓存键口径不同：DMM 去分隔符（`SSIS-001` → `SSIS001`），D2PASS 保留 `-` / `_` 的区别。
2. **只用自己需要的接口**。只要商品 ID 就用 `/cid`，比 `/dmm` 快且省上游请求。
3. **封面与预告片是源站直链**，本服务不代理媒体二进制。客户端所在网络若无法访问日本源站，图片与视频仍可能加载失败 —— 这与查询接口无关。**接入扩展后，用户网络必须走日本出口代理才能正常看到封面/预告片**（见顶部前提）。
4. **`preview_url` 可能为空**：源站没给预告片时返回 `null`，不是错误。
5. **批量优先**：多个番号用 `/batch`，比逐条请求少一次往返，D2PASS 侧还省限流额度。
