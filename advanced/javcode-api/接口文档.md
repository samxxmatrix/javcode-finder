## 1. 基本信息

**服务地址**：`https://<your-project>.vercel.app`（部署后得到一个域名，所有接口共用）

### 鉴权（本版收紧）

| 项 | 规则 |
|---|---|
| API Key | **必须**。服务端必须配置 `API_KEY`，部署时不能留空 |
| 传递方式 | `?key=YOUR_API_KEY` 或请求头 `x-api-key: YOUR_API_KEY`（二选一，请求头优先） |
| 覆盖范围 | **所有接口，包括 `/health`**，没有例外 |
| 没带 Key | `401 / 40101 MISSING_API_KEY` |
| Key 错误 | `403 / 40301 INVALID_API_KEY` |
| 服务端未配置 `API_KEY` | 属部署错误，**所有请求返回 503 配置错误**，不得退化成公开接口 |

**部署区域**：东京 `hnd1`（FALENO 源站对大陆出口有拦截）。部署时必须填 `API_KEY`；`REDIS_URL` 可选，其余均有默认值。

## 2. 接口列表（7 条）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/health` | 健康检查：**同时验证服务可用与 API Key 正确** |
| GET | `/dmm/:code` | 有码番号完整查询 |
| GET | `/dmm/batch?codes=A,B,C` | **有码批量查询**（本版新增） |
| GET | `/cid/:code` | 仅查商品 ID，轻量 |
| GET | `/faleno/:code` | FALENO 作品页查询 |
| GET | `/d2pass/:code` | 无码番号单查 |
| GET | `/d2pass/batch?codes=A,B,C` | 无码批量查询 |

所有接口都需要 Key。

**不提供的接口**：旧的无约束根路径 `/:code`、旧的 D2PASS `/batch?codes=`、`?mode=batch`、以及 `/api?code=...` 的直接对外调用（仅作为内部转发目标）。

批量一律走分路径，与现有显式前缀风格一致；dispatcher 按前缀分发到两个 handler 各自的批量实现，**不在入口做跨源合并**。

## 3. 健康检查

```
GET /health?key=YOUR_API_KEY
```

| 项 | 值 |
|---|---|
| 鉴权 | **需要**，与业务接口同一把 Key |
| 成功 | HTTP 200，`{ "ok": true, "service": "javcode-api" }` |
| 失败 | `40101`（没带 Key）/ `40301`（Key 错）/ `50301`（服务自身异常） |
| 响应头 | `Cache-Control: no-store`，不得被 CDN 缓存 |
| 上游访问 | 无。只探活 + 验 Key，不查番号、不碰源站 |

**一次请求同时验证两件事**：服务活着、Key 正确。扩展「番号查询」开关打开时调用它，8 秒内没返回按超时处理：

| 返回 | 界面 |
|---|---|
| 200 | 已启用 |
| 40101 / 40301 | 未启用 + 「密钥无效」/「缺少密钥」 |
| 超时 / 50301 | 未启用 + 「服务不可达」/「请求超时」 |

## 4. 公共参数

| 参数 | 适用端点 | 说明 |
|---|---|---|
| `key` | 全部 | **必填**；与 `x-api-key` 二选一 |
| `codes` | 两个 `/batch` | 逗号分隔的番号列表，去重后最多 50 个 |
| `refresh=1` | 所有查询接口 | 强制绕过缓存重新解析；响应 `no-store` |
| `debug=1` | 所有查询接口 | 返回解析中间状态；响应 `no-store` |
| `quality=NNNp` | `/dmm`、`/d2pass`（含批量） | 覆盖本次清晰度偏好；只认 3–4 位数字 + `p`。`/cid`、`/faleno` 忽略 |
| `no_preview=1` | `/d2pass`（含批量） | 只要元数据、跳过预告片解析；响应 `no-store` |

`refresh` / `debug` / `quality` / `no_preview` 都会改变响应内容，一律不进 CDN 缓存。

## 5. 单条响应字段

### 5.1 `/dmm/:code`、`/cid/:code`、`/faleno/:code`

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | String | 查询番号（大写） |
| `cid` | String | DMM 商品 ID（**扩展以此字段判定查询成功**） |
| `channel` | String | `digital` / `mono`；FALENO 固定 `faleno` |
| `title` / `short_title` | String | 剧情介绍（长文）/ 标题（短） |
| `cover_url` | String | 封面大图 |
| `preview_url` | String 或 null | 已按偏好选好的预告片 mp4 |
| `preview_quality` | String 或 null | 实际选中档位，如 `432p` |
| `preview_qualities` | Array | 全部档位表 `[{quality,height,resolution,bandwidth,url}]`，按分辨率升序 |
| `quality` | Number 或 null | 本次生效的覆盖值，参与缓存口径 |
| `actresses` | Array | 出演者名数组 |
| `delivery_date` / `sale_date` | String 或 null | 原始抓取值，不归一化 |
| `detail_url` | String | 详情页 |
| `v` | Number | 条目口径版本，当前 4 |
| `cached` | Boolean | 是否命中缓存 |

- `/cid/:code` 只返回 `v` / `code` / `quality` / `cid` / `channel` / `cached`，不抓详情页。
- `/faleno/:code` 字段同上，但**不含 `quality` / `preview_quality` / `preview_qualities`**；扩展复用 DMM 解析器。

### 5.2 `/d2pass/:code`

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | String | 归一化番号（大写，**保留原分隔符**；扩展以此字段判定成功） |
| `class` | String | `uncensored` / `censored` / `amateur` / `unknown` |
| `title` / `short_title` | String | 剧情介绍 / 标题 |
| `cover_url` / `cover_url_alt` | String | 封面 / 源站封面兜底 |
| `preview_url` | String 或 null | 预告片直链 |
| `preview_type` | String | `mp4` 或 `hls` |
| `preview_quality` | String | `480p` / `360p` / `240p` / `720p` / `1080p` / `single` / `sample_low` / `hls` 等 |
| `actress` | String 或 null | 多人用 `、` 连接；名字中的空格属于名字本身 |
| `release_date` | String 或 null | 发行日，不归一化 |
| `site_id` / `site_name` | String | 命中的加盟站 |
| `source_url` | String | 源站详情页 |
| `d2pass_url` | String 或 null | D2Pass 商品页 |
| `match` | String | `exact` / `backlink` / `fuzzy` |
| `cached` | Boolean | 是否命中缓存 |

> DMM 用 `cid` 判成功、D2PASS 用 `code` 判成功，两套响应结构刻意保留，不做统一 DTO。

## 6. 批量响应（两个分支统一）

```
GET /dmm/batch?codes=A,B,C&key=...
GET /d2pass/batch?codes=A,B,C&key=...
```

| 项 | 规则 |
|---|---|
| 上限 | 去重后 **50 个**（`BATCH_MAX`，两个分支共用），超过返回 `400 / 40003 TOO_MANY_CODES` |
| 响应 | `{ "results": { "CODE": {...单条响应} }, "errors": { "CODE": {...错误对象} }, "cached": { "CODE": true } }` |
| HTTP 状态 | 固定 200，**部分成功**：单个番号失败不影响其他番号，调用方按 `errors` 逐条判定 |
| 早退 | D2PASS 对有码 / 素人 / 乱码番号就地放入 `errors`，不进限流、不碰缓存 |
| 限流 | D2PASS 批量**整批只计 1 次**限流（与 codes 数量无关） |
| 并发 | DMM 批量需服务端并发控制（建议 5）与统一超时预算，避免 50 个番号同时打上游 |
| 响应体积 | 单条 DMM 完整响应含 `preview_qualities` 数组，批量结果需控制在 Vercel 4.5 MB 响应体上限内 |

两个批量的 `refresh=1` 对该批全部番号生效；`quality=` 对该批统一生效。

## 7. 错误码（全站一张表）

| HTTP | code | error | 原因 |
|---|---|---|---|
| 400 | 40001 | MISSING_CODE | 缺少番号或 `codes` 为空 |
| 400 | 40002 | INVALID_CODE | 番号格式无法归一化（D2PASS） |
| 400 | 40003 | TOO_MANY_CODES | 批量超过 50 个 |
| 401 | 40101 | MISSING_API_KEY | 缺少 API Key |
| 403 | 40301 | INVALID_API_KEY | API Key 错误 |
| 404 | 40401 | ITEM_NOT_FOUND | 确认查无此番号 |
| 429 | 42901 | RATE_LIMITED | 触发限流（仅 D2PASS 分支） |
| 500 | 50001 | INTERNAL_SERVER_ERROR | 服务内部错误 |
| 503 | 50301 | SOURCE_UNAVAILABLE | 上游无法定性，或未配置 `API_KEY` 的部署错误 |

**404 与 503 必须区分**：只有「确认查无」报 404；上游抖动一律 503，带 `Retry-After: 5`，不写任何缓存。

## 8. 缓存与响应头

| 分支 | 成功响应 | 说明 |
|---|---|---|
| `/dmm`、`/cid`、`/faleno`、DMM 批量 | **不加** CDN 缓存头 | 否则吃掉 `refresh=1` 与 `quality=` |
| `/d2pass`、D2PASS 批量 | `public, s-maxage=86400, stale-while-revalidate=604800` | 与现状一致 |
| 带 `refresh` / `debug` / `quality` / `no_preview` | `no-store` | 一律不进 CDN |
| `/health` | `no-store` | — |
| 任何错误 | `no-store` | — |

服务端缓存（Redis 可选）：DMM 裸番号 / `CID:` / `FALENO:`（资料齐全永久、不全 6 小时、无负缓存）；D2PASS `D2P:`（永久）/ `D2P:NF:`（6 小时）/ `D2P:RL:*`（限流 60 秒）。未配 `REDIS_URL` 时 DMM 直抓、D2PASS 退进程内缓存，均不报错。

两套缓存值结构刻意不统一（裸对象 vs 信封），共享层只负责读写，不解释内容。

## 9. 环境变量（本版统一）

### 9.1 清晰度偏好：单一变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `PREVIEW_QUALITY` | **`320p`** | **两个分支共用**。DMM 解析成目标高度并选最接近的真实档位；D2PASS 按下方映射表换算成站点实际存在的档位后提到优先级首位 |
| `BATCH_MAX` | `50` | 两个批量的共同上限 |
| `PREVIEW_ENABLED` | `true` | 全局开关：是否解析预告片 |
| `PREVIEW_VERIFY` | `true` | 全局开关：是否探活预告片地址 |

单请求仍可用 `?quality=NNNp` 覆盖，两边写法一致。

**废弃**：`PREVIEW_HEIGHT_MIN` / `PREVIEW_HEIGHT_MAX` / `PREVIEW_QUALITY_ORDER` / `PREVIEW_HEYZO_ORDER`。

**保留内部差异（不强行统一算法）**：

- DMM 档位来自按片枚举的 HLS playlist，高度是真实值；D2PASS 是静态文件名候选集 + 探活。
- **`PREVIEW_QUALITY` 是目标偏好，不是精确档位**。D2PASS 的默认候选列表是 `480p / 360p / 240p / 720p / 1080p`，**不含 `320p`**：若直接把 `320p` 提到首位，站点根本没有该变体，首次探活必然失败，随后回退到 `480p` —— 等于多一次无效请求，且实际默认档位没有变。因此服务端必须把目标值就近映射到实际存在的档位：

  | 目标 | D2PASS 普通站点 | HEYZO |
  |---|---|---|
  | `320p` | `360p`（就近偏高） | `sample_low` |
  | `240p` | `240p` | `sample_low` |
  | `480p` | `480p` | `sample` |
  | `720p` 及以上 | 对应档位 | `sample_hd` |

- HEYZO 的档位标签不是像素（`sample_low` / `sample` / `sample_hd`），`single` / `hls` / `d2pass` 等标签也没有高度概念，只能靠映射表处理。
- `?quality=` 明确给出站点存在的档位时直接使用该档，不再做映射。

因此统一的是**偏好入口**，不是选档算法；两套实现仍留在各自 lib 里。

### 9.2 其余变量

`API_KEY`（**必填**）、`REDIS_URL`（可选）、`RATE_LIMIT_PER_MIN`（D2PASS 限流，默认 120）、`FALENO_ORIGIN`、`PROBE_BUDGET_MS`、`INCOMPLETE_CACHE_TTL_SECONDS`、`SOURCE_TIMEOUT_MS`、`D2PASS_TIMEOUT_MS`、`TOTAL_BUDGET_MS`、`NEGATIVE_TTL_HOURS`、`D2PASS_USE_RSC`、`DISABLED_SITES`、`SITE_PROXY_<SITE_ID>`。

## 10. 调用须知

1. **所有接口都要带 Key**，`/health` 也不例外；未配 Key 属部署错误。
2. **限流只作用于 D2PASS 分支**（单查与批量都算，批量整批算 1 次），DMM 分支不参与 —— 保持既有行为。
3. 番号归一化两套语义不同：DMM 去分隔符做缓存键，D2PASS 保留 `-` / `_` 的区别；调用方不要替服务端归一化。
4. 缓存键只接受 `^[A-Z0-9][A-Z0-9._-]{1,31}$`；不满足时不读不写缓存，但请求照常返回。
5. 封面与预告片均为**源站直链**，本反代不代理任何媒体二进制。
6. 多个番号优先用对应分支的 `/batch`，比逐条请求更省请求数与限流额度。

## 12. 第 2 版确认点

1. 分路径批量：`/dmm/batch`、`/d2pass/batch`，上限 50，统一 `{results, errors, cached}` 与部分成功语义。
2. API Key 必填，覆盖所有接口；服务端未配置时拒绝请求，不再公开。
3. `/health` 需 Key，200 同时证明服务可用与 Key 正确；40101/40301 直接映射为界面「密钥无效」。
4. 单一 `PREVIEW_QUALITY`（默认 `320p`）统一两边偏好，D2PASS 侧按映射表就近换算；废弃四个旧档位变量；内部两套选档算法保留。
